# 实测手册 · 四项「非机器可验」验收（人做项）

> 2026-10-19 · 主策划 · 配套 `04_项目管理/验收记录_v0.7.md`（登记与状态在那边，**步骤与记录表在这边**）
> 这四项的共同点：**AI 做不了**（没有耳朵/眼睛/组织能力），机器也验不了（要真机外放、要人眼、要真实环境光）。
> 每项都写死：**产物 → 步骤 → 判据 → 记录表 → 不合格怎么办**。照抄执行，不要临场发明。

## 通用纪律

| # | 规则 |
| --- | --- |
| G1 | **执行人**：测试运营（现实里就是你 / 一个同事）。**判定人**：测试运营签字，主策划只定判据。 |
| G2 | **一次只测一项**。同一台机器上连测四项，环境光/音量/注意力会串味。 |
| G3 | **记录只认三样**：原始产物（截图/录音）、数字、结论。不写"感觉还行"。 |
| G4 | 结果一律回写 `验收记录_v0.7.md` 表一对应行：`未执行` → `有证据-过` / `有证据-红`，并把产物路径填进"证据"列。 |
| G5 | 时间不够就**只做 A2 + A4**（这两项错了最难事后发现）；C1/C2 可以延后，但必须保持"未执行"。 |

## A2 · 三轨盲听定默认曲

**产物**：8 份问卷记录（最少 5 份）+ 一句话结论。

**前置**：`F1` 已合入（循环调度修好），否则听的是每圈叠一次的曲子 → 结论无效。

**步骤**
1. 打开 `temp/bgm_ab/bgm_compare.html`（试听页），确认三轨都能播。
2. 招募 5–8 人（**不含执行人自己**；同事、朋友、家人均可）。
3. 每人：**不告诉曲名**、顺序随机；每曲听 **20 秒**，中间不解释。
4. 逐曲问 Q1–Q3（见下表），三曲听完问 Q4。
5. 填记录表；算 Q1「能」的人数、Q2「能」的人数。

## A4 · 手机外放低频（110–147Hz 还听得见吗）

**产物**：2 段录音（安卓 / iPhone 各 1）+ 2 份记录。

**为什么必须真机**：手机小喇叭基本没有 150Hz 以下（典型截止 300–500Hz）。桌面音箱能听见，说明不了任何事。而助眠的使用场景就是**床头放手机**。

**设备**：中端安卓 1 台 + iPhone 1 台（有自己的手机就够，不需要设备池）。

**步骤**
1. 把 `原型/dista_prototype.html` 传到手机：微信文件传输 / 邮件附件 / 电脑起局域网静态服务，任选。
2. 手机浏览器打开 `…/dista_prototype.html?scene=night_station`（这段播 `lofi`），**点一下屏幕**解锁音频（iOS 必须手势）。
3. **音量固定 60%**，手机**外放**（不戴耳机、不接音箱），平放桌面。
4. 先**静音 10 秒**（点右上角静音图标）——这是对照基线。
5. 取消静音，听 **30 秒**；再切 `?scene=minimal`（`ambient`，弦乐垫）听 30 秒。
6. 用另一台手机录 15 秒（录"手机外放的声音"，不是内录）。

**判据**（把"明显可闻"操作化成两问）

| # | 问题（问自己，二选一） | 判"可闻"的条件 |
| --- | --- | --- |
| A4-1 | 低音层能不能**听出音高**（能哼出"咚—咚—"的高低），还是只有一片沙沙？ | 能听出音高 |
| A4-2 | 与第 4 步的静音段相比，低音的**存在感**是"多了一层"还是"基本没变"？ | 明显多一层 |

- 两台机子**都**满足 A4-1 且 A4-2 → **通过**。
- 任一台只满足一项 → **不通过**，走 A4-b。

**记录表**

| 设备 | 型号 | 系统 | 静音段描述 | lofi 低音可闻？ | 能听出音高？ | ambient 弦乐垫 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 安卓 | | | | 是 / 否 | 是 / 否 | | 通过 / 不通过 |
| iPhone | | | | 是 / 否 | 是 / 否 | | 通过 / 不通过 |

**不合格怎么办**：加一层 **+1 八度（220–294Hz）钢琴单音，电平 −24dB**（规格 §3.4 A4-b），**不做 150Hz 高通**（会把仅剩的低音再削一次）。加完必须回归：低频冲击 ≤12dB、动态 ≤7dB、接缝 ≤4dB（`audio_check`）。

## C2 · 浅底（`noon_window`）绿框可见度

**产物**：3 张截图 + 5 份记录。

**为什么要人眼**：绿框在米色底上的亮度对比只有 **1.75:1**（D-042 已签字接受，因为 WCAG 4.5:1 物理不可达）。机器只能算数字，"一眼找不找得到"只能人看，而且必须在**白天环境光**下看。

**步骤**
1. 出 3 张同关卡、同物体、同 `pressMs` 的截图，**只换场景**：
   ```
   ?scene=noon_window&screen=play&lvl=1&hour=13
   ?scene=night_station&screen=play&lvl=1&hour=21
   ?scene=minimal&screen=play&lvl=1&hour=21
   ```
   命令示例（已是本机验证过的写法）：
   ```
   msedge --headless=new --disable-gpu --no-sandbox --window-size=720,1280 `
     --virtual-time-budget=2000 --screenshot="noon.png" "file:///…/dista_prototype.html?scene=noon_window&screen=play&lvl=1&hour=13"
   ```
2. 顺序打乱，编号 A/B/C（不给名字）。
3. 找 5 人，**白天、窗边或开灯**（不要在暗房间做，那测的是 night）。
4. 每人：展示 A 图，说"开始"后**数 1 秒**（用手机秒表或心里默数），1 秒时把图盖住，问"绿框在哪一边？指出来"。
5. 三张图各做一次（间隔 30 秒，避免记忆）。

**判据**

| # | 判据 | 通过线 |
| --- | --- | --- |
| C2-1 | 1 秒内能**指出**绿框位置（左/中/右 + 大致高度） | 5 人里 ≥4 人（`noon` 那张） |
| C2-2 | `noon` 与 `night` 两张的"位置指认正确率"差 ≤1 人 | 否则说明浅底确实吃亏 |
| C2-3 | 环-背景亮度比 ≥1.7:1、色相差 ≥90°、环宽 ≤1.5px | 复算（已有值 1.75:1 / 118° / 1px） |

**记录表**

| 受试 | 环境光（窗边/开灯/暗） | A 图：指认 | B 图：指认 | C 图：指认 | 用时（秒） |
| --- | --- | --- | --- | --- | --- |
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |
| 4 | | | | | |
| 5 | | | | | |

**不合格怎么办**（只能在上限内微调，不许破 D-042）
1. 先把环 α 从 **0.50 → 0.55**（`scenes.json.frameStyleParams.ringAlpha`，上限 0.55），重测；
2. 再把环宽 **1.0 → 1.5px**（上限 1.5），重测；
3. 仍不过 → 说明"白天亮底"这条路本身不成立，**回来找我复议 D-042**（选项：noon 不进自动轮换 / 只手动选）。不许自己在代码里加阴影或改描边色。

## C1 · 三场景盲测（3 米 / 2 秒）

**产物**：1 张并排图（3 张截图横向拼接）+ 5 份记录。

> **已经出好了（2026-10-19 07:00，可直接拿去测）**：
> `04_项目管理/验收截图/cmp_noon.png`、`cmp_night.png`、`cmp_minimal.png`（720×1280，同关卡 L1、同 `virtual-time-budget=2000`）
> 与并排图 `04_项目管理/验收截图/cmp_scenes_3way.png`（2160×1280）。
> 要重出就按下面第 1–2 步；**换参数（关卡/物体/时间点）必须三张一起重出**，否则差异会混进结论。

**步骤**
1. 用与 C2 相同的三条命令出图（**同关卡、同物体、同 `pressMs`**，只换场景）。
2. 横向拼成一张 2160×1280 的并排图（Windows 画图 / 任意拼图工具都行；不留间隙，不加标注）。
3. 在屏幕上**全屏**显示，受试者后退到能看见整张图的 **3 米**处（看不清就往近站，直到能看清绿框）。
4. 给 **2 秒**，然后遮住，问三个问题：
   - Q1：「这三张是不是同一个地方？」（是 / 不是）
   - Q2：「分别像什么地方？」（各说一个词即可）
   - Q3：「哪一张最不像另外两张？」
5. 记录。**不要提示"场景"这个词**。

**判据**

| # | 判据 | 通过线 |
| --- | --- | --- |
| C1-1 | Q1 答"不是" | 5 人里 ≥4 人（这就是 D-077 的"能区分"） |
| C1-2 | Q2 三张能给出**互不相同**的描述词 | ≥3 人 |
| C1-3 | Q3 能指出一张"最不像"的 | ≥3 人（说明有一个场景已经形成独立印象） |

> 现状预期：`night` 与 `noon` 大概率能过，`minimal` 是这轮新增台灯剪影后的变量——若 C1-1 过了但 C1-3 都指向 `noon`，说明台灯还没立住，需要再加权（α 0.045 → 0.055 或换更"住人"的剪影）。

**记录表**

**不合格怎么办**
1. 先确认不是"三张图物体位置不同"造成的误判（同 `lvl` 同 `press` 同 `fxAt`）；
2. 只允许调 `minimal` 的剪影：α 0.045 → 0.055（worstAddPct 会到 ~8.4pp，仍 ≤18）；或换一个更"住人"的剪影（台灯→窗框），但**换形状要重算预算并回写美术 §3.5**；
3. 不许动 `night` / `noon`（它们已经过了）。
