**一句话**：判定 = 轮廓重合面积（不是中心点）；绿框坐标只由 Layout 决定、与时间无关；随机只动 `cycleMs`（±jitter），不动路径与 `uStar` 的相对关系；**完美时机在数学上唯一存在**（`buildLevel` 有安全网：路径离 C > 0.5px 直接抛错）。

## 3. 关键公式

| 项 | 公式 | 备注 |
| --- | --- | --- |
| 重合率 | `pct = 交集 / max(物体面积, 目标面积) × 100` | `overlapAreaExact` 扫描线+梯形，精确解；栅格解仅做回归校验 |
| 完美时机 | `uStar` = 路径上离 C 最近点的弧长比例；`tStar` 解 `u(t)=uStar`（二分 40 次） | 7 条模板落点误差 ≤ 0.0075px |
| 两段变速 | 前 40% 周期 ×k、后 60% ×(2−k)，总距离不变：`v0 = L / cycle / (0.4k+0.6(2−k))` | 切换点固定 = 可练可背 |
| 旋转 | `rot(t)=startRot+360·turns·t/cycle`，`startRot=normDeg(−360·turns·tStar/cycle)` | ⇒ `rot(tStar)≡0`，完美时机正好转正 |
| 多物体 | `pct` = 各物体平均；`pass` = **每个**物体 ≥ passRate；`star3` = 平均 ≥ star3Rate | 双车道共用同一 `perfectMs` |
| 分数 | `round(base × min(2, 1+0.1·combo) × MODE_COEF)` | base 1000/600/350/150/0 |
| 时机 | `Δ = wrap(pressMs − perfectMs, ±cycle/2)`，每 mover 用自己 cycle 折算；`|Δ|≤16.7ms → onTime` | 早/晚文案用 `TimingText` |

## 9. v0.4 运动调制（task-10）

新增 7 列：`season / sine_amp / sine_period_ms / **sine_phase** / inertia_px / inertia_hz / inertia_phase`（`assets/scripts/core/LevelStore.ts` 的 `MOTION_RANGES` 校验；缺列默认 0 → 旧表零改动可用）。其中 `sine_phase` 是 v0.5 新增（正弦起始相位，0 与 0.5 = 两种呼吸节奏）。

### 9.1 正弦速度调制（改「何时到」，v0.5 起含相位）

```
v(t) = v0 · stage(t) · (1 + amp·sin(2π(t/T + φ)))        φ = sine_phase ∈ [0,1]
∫₀ᵗ = t + (amp·T/2π)·[cos(2πφ) − cos(2π(t/T + φ))]      ← 解析式，不做数值积分
u(t) = [k1·I(ts) + k2·(I(t) − I(ts))] / [k1·I(ts) + k2·(I(T) − I(ts))]
```
- `amp < 1 ⇒ 速度恒正 ⇒ u(t) 严格单调 ⇒ 完美时机唯一`。**相位只改速度大小、不改方向**，所以 φ 怎么调都不会造出第二个卡位点；`tStar` 由二分 40 次重求（`tStarOfMotion`）。
- **S8 逐位兼容的两条分支（都标注禁改）**：`sineAmp === 0` → `uAt` 走 v0.3 原算式 `uAtUnmodulated`；`phase === 0` → `sineIntegral` 走 `t + (amp/w)(1 − cos(wt))`。**不是数学等价，是同一串浮点运算**，季 1 三窗口因此与 v0.3 逐位相同。
- 双峰：正弦数学上不会造双峰；`cycle_ms / sine_period_ms` 为整数比只影响窗口左右对称度（`inspectLevels` 一条汇总提示，不算错误）。
- **v0.5 相位语义（以实测为准）**：`v(tStar) = v0·(1 + amp·sin(2π(tStar/T_sine + φ)))`，而 **`tStar` 本身随 φ 移动**（由 `u(tStar)=uStar` 决定），所以**相位对窗口的作用没有闭式解**，不能背「0.25 最慢 / 0.75 最快」这类口诀——实测反例：L49（cycle 1629 / T_sine 815，`cycle ≈ 2·T_sine`）里 φ=0.25 让完美点**最快**（窗口最窄 92.3ms）、φ=0.75 **最慢**（最宽 108.9ms）。
- 因此本层的纪律是：**只断言性质，不断言物理猜测**。窗口宽度/早晚比一律当**实测值**打表（`geometry_test [S9b]` 四相位表 + 单关扫描 `tools/phase_probe.mjs`）。
- 已实测的两条结论（写进这里供策划引用）：① 相位与正弦频率对窗口都是 **±10% 量级的微调旋钮**，而季内相邻关的窗口差是 30%+ → **相位不该出现在机制表里，应归入调参表**；② **φ=0.5 不会「互换早/晚」**（45 关实测 0 关互换）——早晚不对称主要由**形状自身在 ±旋转下的不对称**与**惯性抖动方向**决定，不是正弦相位决定的。
- **实测基线（45 个正弦关，seed=0）**：`φ0 vs φ0.5` 平均窗宽 **61.8 vs 59.7ms（−3.5%）**，早>晚的关数 **28/45 vs 23/45**；`φ0.25 vs φ0.75` **61.1 vs 60.6ms**，平均最宽/最窄 **1.12×**。
- **踩坑记录（活标本，留给以后的人）**：曾按 `tStar ≈ T_sine/2` 推出闭式 `v(tStar)=v0(1−amp·sin2πφ)`，据此在 `[S9b]` 汇总里写了「φ=0.5 应早/晚互换、窗宽应几乎相同」。实测 45 关 **0 关互换**、窗宽差 −3.5%。
  错因：`tStar` 由 `u(tStar)=uStar` 决定、**并随 φ 移动**，`tStar/T_sine` 不一定是 1/2（L49：`cycle/T_sine≈2`，`w·tStar≈2π` ⇒ φ=0.25 反而**最快**、窗口最窄）。
  教训：**闭式推导只在变量的取值范围内成立**；把猜想写进断言，会把正确实现判成错的。代码里已把这条纪律钉在 `[S9b]` 注释上。

### 9.2 惯性位移（只叠位移，不叠转角）

```
offset(t) = A · sin(2π·f·(t − tStar)) · (cos 2πφ, sin 2πφ)
pose(t)   = pathPoint(u(t)) + offset(t)     // rot 不变：rot = startRot + 360·turns·t/cycle
```
- **t = tStar 时 offset ≡ 0** ⇒ 完美时机仍是 100%，`godWindow` 不会因为惯性变成空窗口；代价是「惯性只影响接近/离开段」（这正是「抖动感」的来源）。
- 振幅严格 = A（不放大）；方向由 `inertia_phase` 决定（0 = 左右抖、0.25 = 上下抖、0.5 = 反向左右抖）——**这是我对「相位」的解释，需主策划确认**（R8）。
- 绝对确定性：无随机、无状态；`zeroMs = tStar` 写在 mover 的附加属性里，双车道各自独立。
- 不改转角是硬要求：叠转角会隐性收窄角度容错，让「容错」变成不可解释的数。

### 9.4 双车道：以第 0 条车道为母版做「y 平移 + x 镜像」

**踩过的坑（v0.4 修）**：原来对每条车道各自 `buildPathPts(C_i)`，而 `arc_*` / `bounce_floor` 的**路径长度随 C.y 变化**（bounce 的第三个顶点就是 C）→ 两条车道 `uStar` 不同 → `tStar` 不同 → 同一帧不可能同时完美。实测 L52（dual + bounce_floor）`pct=50%`、位移 228px、角偏 78.6°。

**现在的做法**：双车道只用第 0 条车道生成一次路径，第 1 条做 `x → 2·cx − x`、`y → y + Δy`。平移与镜像是等距变换 ⇒ **逐段等长 ⇒ uStar 相同 ⇒ tStar 相同**，`perfectMs` 天然一致；同时 `buildLevel` 末尾有硬断言（两车道 `tStar` 差 >0.05ms 直接抛错），`geometry_test [3]` 也有同款断言（每个 mover 在 `perfectMs` 的姿态必须落在自己车道中心 ≤0.05px）。

⚠️ 已知副作用（只影响视觉、不影响判定）：`dual + bounce_floor/arc_*` 时车道 1 的路径是车道 0 的平移副本，下平移 390px 后可能有顶点跑到可画区外（bounce 的触地点 → y≈1360，超出 1280 屏高）。**判定仍然正确**（uStar/tStar 一致），但画面会「飞出屏幕」。当前数据已把所有双物体关固定为 `h_line`，所以不触发；若以后要 dual+弧线，需要主策划定一条「车道 1 的路径垂直压缩」规则（会改长度，必须重新校准窗口）。

### 9.6 v0.6 双物体错拍（`phase_2` / `cycle_2_ms` / `judgeNearest`）

**语义**：错拍关 = 一关按两次，每次定格「当前最接近绿框的那个」，两次都合格才算过关（不是两个窗口求交集，交集可能为 0）。

| 字段 | 范围 | 缺省 | 语义 |
| --- | --- | --- | --- |
| `phase_2` | 0–0.5 | 0 | 第二个 mover 的**时间轴**后移 `phase_2 × cycle_2`（位置不变，仍是车道 0 的等距变换） |
| `cycle_2_ms` | 0 或 600–4000 | 0 | 第二个 mover 的周期；0 = 与第一个相同（微扰用同一个倍率，不额外抽取随机数） |

实现要点：
- `localT(mover, t)`：`offsetMs === 0` 时返回 `wrapT(t, cycle)`（**零偏移兼容分支，禁改**）——S13 靠它保证「加字段不改变同步关」；`uAt / poseAt / inertiaOffsetOf` 全部走 `localT`，所以「位置」与「时间」天然分离。
- `mover.perfectMs`（附加属性 `timing`）= 自身 tStar + offsetMs；`rt.perfectMs` 保留 = mover 0 的值（同步关两者相等，兼容旧调用）。
- `judgeNearest(rt, t, skipIdx, combo)` → `{ moverIndex, pct, rating, baseScore, score, timing, objects }`：取**不在 skipIdx 里**的 mover 中 pct 最大者；`objects` **只含选中的那个**（原型直接拿去画热力图）；全部在 skipIdx 里 → 返回 `null`。**core 不持有状态**，谁已定格由调用方维护。
- `judge()` **未改动**：同步关继续用它取 min（S15 断言两者 per-object pct 一致）。
- `duoVerdict(rt, judged, combo)`：关卡级结算——评级取两次里较差者、分数只算一次（最差评级的基础分）、任一不合格 → 整关失败；重复计次会被忽略（幂等，配合 S16）。
- 窗口：**`hitWindow/godWindow/starWindow/windowMetrics` 内部自动分支**——运行时有任一 mover 的 `offsetMs≠0` 就走「每 mover 各自 perfectMs」的 per-mover 窗口，关卡窗口 = **较窄者**；同步关仍走 v0.5 原路径（逐位相同）。导出额外写 `hitWindowByMover / godWindowByMover / perfectMsByMover`。
- **时间基准纪律（踩过两次）**：`rt.perfectMs` 只是 **mover0** 的值，**只对同步关**等价于「全关一个」。任何围着完美时刻的代码（窗口扫描、几何断言、双车道校验）在错拍关都必须换成 `moverTiming(mover).perfectMs` / `Judge.perfectMsOf(rt, i)`。`poseAt` 内部曾经「先 localT 再传给 uAt，而 uAt 又减一次 offset」，正是 L50/L60「mover1 窗口=0」的根因——现在 `poseAt` 往 `uAt` 传**原始** `tMs`，offset 只在 `localT` 里减一次。
- `sim`：错拍关按「两次独立按下」建模（各自误差、任一不合格即失败），统计用**最差 pct** 判三星/神级/失败。
