# 04_项目管理 · 谁在什么时候交付了什么

| 目录 / 文件 | 内容 | 更新人 | 频率 |
| --- | --- | --- | --- |
| `会议纪要/` | 每次 15 分钟站会的结论与待办 | 主策划 | 每周 2 次 |
| `排期表/` | 两周一迭代的任务、负责人、依赖 | 主策划 | 每迭代 1 版 |
| `BUG清单/` | 现象、复现步骤、严重级、影响面 | 测试运营 | 随时 |
| `版本日志/` | 版本号、变更内容、已知问题 | 测试运营 | 每次发版 |
| `决策记录.md` | 谁拍的板、理由、何时复盘 | 拍板人本人 | 随时 |

## BUG 严重级（先定口径，避免吵）

| 级别 | 定义 | 处理时限 |
| --- | --- | --- |
| P0 | 玩不下去 / 判定错误 / 崩溃丢档 | 当天修，不修不发版 |
| P1 | 主要功能不可用或有明显错误反馈 | 本迭代内修 |
| P2 | 体验瑕疵、文案错、非核心路径 | 下迭代 |
| P3 | 建议项 | 排进 backlog |

## 迭代出口（三个条件同时满足才算完）

1. 有一个能连贯玩通的包（不是纯文档迭代）；
2. 本迭代新增判定逻辑有单测/模拟跑过；
3. 版本日志写清「本版能玩到什么程度」。
