> 你的原话：**按一次就判定了，没有按第二次的机会。**
> 下面是我按这句去复现、定位、修掉的三处，全部已落库并复跑断言。

## 一、先说结论：这不是"一次就结算"，是**第一次点击被吃掉了**

L50 是错拍关，代码层面**一次点击不可能结算**（要有两次定格才 `duoVerdict`）。
用原型内部 API 直接驱动验证过：

```
第一次按后  scene=feedback frozen=[true,false] judged=1   ← 只定格 1 个，不会结算
解冻后      scene=play     frozen=[true,false] judged=1   ← 回到可操作
第二次按后  frozen=[true,true]  judged=2
结算后      pass=true  worstPct=100
```

所以"看起来按一次就判定"的真实链条是：**第一下点击被系统吃掉了，你真正对准的那一下变成了第二次，于是当场结算**。吃掉它的有两条路径，我都堵了。

## 二、三处修复

### ① 首次点击被"解锁音频"吃掉（主因）

`handlePressAt` 里 `audioUnlock()` 的返回值原来被忽略，于是**同一个点击既解锁音频、又当游戏按下**。
从试玩入口（`?screen=play`）直接进关时玩家没点过任何东西，第一下点击就是这么被消耗的。

**修**：本会话**第一次成功解锁音频的点击只用于解锁，不算判定**；而且**只吞局内那一下**（首页按钮、图鉴点击不吞，避免第一次点「闯关挑战」没反应）。

### ② 400ms 冻结里点击被静默丢弃（次因）

原来每次定格后有 400ms 冻结，期间**输入是锁的**且没有任何提示，连点第二下会"没反应"，玩家以为游戏卡住/已结束。

**修**：
- 冻结 **400ms → 200ms**（死区减半）；
- 冻结期间在暂停键外画**倒计时环**；
- 冻结结束后：**已定格的物体压暗（α0.32）**，**未定格的那个绿框脉动**——"谁还要按"一眼可见。

### ③ 试过又回退的方案（记录在此，避免以后重复踩）

"把冻结里的点击排队，解冻瞬间判一次"——实测会把玩家的连点**提前判掉**（那一刻多半不在第二个物体的窗口内），直接判失败、扣机会、两个都重置。**比静默丢弃更糟，已回退。**
