## 2. 接入 5 步（编辑器里照着点）

1. **新建场景**：`assets/scenes/GameMain.scene`，用 3.8 默认 2D 场景即可（自带 `Canvas` + `Camera`），把场景里默认的示例节点删掉，**只留 Canvas**。Boot 只认名为 `Canvas` 的根节点（`find('Canvas')`）；找不到 / 没有 `Canvas` 组件 / Canvas 下没有 `Camera`，会在 Console 打印明确错误并中止，**不会自己造 Camera**。
2. **挂 Boot**：选中 `Canvas` → Add Component → 自定义脚本 → `Boot`。**不需要拖任何 @property**（Boot 没有对外字段，全部代码建）。
3. **放两个 JSON**（必须叫这两个名字，扩展名编辑器自动补）：
   - `assets/resources/config/levels.json` ✅ 已生成
   - `assets/resources/config/shapes.json` ✅ 已由 `tools/export_levels.mjs` 从 `assets/config/shapes.json` 同步（导出工具汇总行会打印「shapes 已同步 N KB」，`--check` 会比对两份是否一致）。运行时只读 resources 这一份。
4. **设分辨率**：项目设置 → 设计分辨率 `720 × 1280`，适配方案 **Fit Width**。Boot 会校验设计分辨率并在不符时 `console.warn`（不崩），但 Fit Width 只能靠这一步手工确认（3.8 没有稳定 getter，见 §6）。
5. **运行**：点预览。Console 应无 error；屏幕出现「定格瞬间 / 点击任意处开始」→ 点任意处 → L1 物体从左侧飞过、绿框静止在中线 → 物体进框时点任意处 → 闪白 → 热力图 → 评级面板（含「按早了 42ms（少转 15°）」）。

> 与根 `README.md` 旧契约的差异（**已报主策划确认**）：旧文档写配置放 `assets/config/`，但 `resources.load` 只能读 `assets/resources/`。因此**运行时读 `assets/resources/config/`**，`assets/config/` 只作为美术交付位/对拍来源。数值的源头仍是 `01_策划文档/levels.csv`。

## 3. 联调契约（已与 client-core 对齐，2026-10-18）

| # | 约定 | 客户端用法 |
| --- | --- | --- |
| 1 | `core/index.ts` 导出 `Core`（完整 CoreApi 对象）+ 具名函数 | `GameBridge` 里 `import { Core, missStrips, objectScaleOf, overlapStrips, starsOfResult } from '../../core/index'` |
| 2 | 热力图：绿 = `overlapStrips(objPts, tgtPts, 6)`（交集），红 = `missStrips(objPts, tgtPts, 6)`（并集−交集）；都是轴对齐 `{x,y,w,h}`、y 向下、±1px | `GameBridge.heatData()` 转发；`HEAT_BAND_PX = 6` 是渲染采样参数，不参与判分 |
| 3 | `objectScaleOf(mover)` → 物体绘制倍率（**按面积**反推，物体面积 = 目标面积） | `LevelRunner` 建 Mover 时传入；`k = shape.size × objectScaleOf` |
| 4 | `judge(rt, pressMs, combo)` 第 3 参 = **连击数**（0,1,2…），系数 core 内部套 `1+0.1n` 上限 2.0 | 传 `runner.comboCount()`，不预乘 |
| 5 | `pressMs` 可超周期，core 内部取模 | 传「本周期 t=0 起算的绝对值」 |
| 6 | `seed` 任意整数，同 seed 逐帧一致（含 jitter 抽签） | `seed = levelId × 1000 + attemptIndex` |
| 7 | `dir` 恒为 1，双物体第二车道 core 已镜像（含 pathPts） | 渲染层**不做**任何镜像 |
| 8 | `result.pass` 已含「两个物体都 ≥ passRate」；`star3` 用平均 pct | 客户端不再二次比较，只用 `pass` / `star3` |
| 9 | 面板星级用 `starsOfResult(rt, result)`（没过 → 0 星；双物体关不会被算成「三星但没过」） | `GameBridge.starsOfResult()` 转发；**不用** `starsOf(pct, def)`，也不自己用 pct 阈值算 |
| 10 | `Core.loadShapes / loadLevels` 收 **JSON 对象**（`JsonAsset.json`），校验失败会 **throw**（带问题清单） | `GameBridge.load()` 里 try/catch → reject → Boot 面板显示一行错误 + `console.error`，不静默吞 |
| 11 | `uAt / poseAt / objectPtsAt / judge` 的 ms 允许任意正负，core 内部取模 | 从 `clock.reset(0)` 起直接传，客户端不预取模 |
| 12 | core 内部 import **无后缀**（`from './Geometry'`；原先的 `.ts` 后缀会触发 tsc `TS5097`，已由 client-core 改掉） | 客户端只 import `'../../core/index'`，路径无需变化 |
| 13 | 热力图红区语义 = **并集 − 交集**（物体探出绿框、绿框没填满，两个方向都算红）；绿区 = 交集 | `Heatmap` 两层分别 fill：红先、绿后；`Heatmap.drawRects` 只做 `toLocalX/toLocalY` 换算 |
| 14 | `levels.json` 每关另带**派生字段**：`hitWindow{earlyMs,lateMs}`、`godWindow`、`starWindow`、`tolDegActual`、`tolPxActual`（seed=0 可复现，每次 `export_levels.mjs` 重算） | **主策划已拍板：本版不消费，且不给玩家看毫秒**（玩家只需要「按早了/按晚了」，毫秒是给策划与测试看的噪音）。唯一保留用途 = **DEV 开关打开时把 `hitWindow` 打到左下角小字**（难度核对），**P2、下一迭代再做**。届时改动两处（不动 core）：`GameBridge` 保留一份 raw json + `Boot` 加一个左下角 Label；`LevelDef` 类型不塞字段 |

## 4. 状态机与 `debugJump`（测试用）

```
HOME ──点击──▶ PLAY ──按下──▶ JUDGED(闪白→热力图→评级) ──停留 900ms 后点击──┐
                 ▲                                                          │
                 │            通过 ──▶ LEVEL_CLEAR ──点击──▶ 下一关 PLAY ◀──┤
                 │            失败且还有次数 ──▶ 自动重进 PLAY（见 T-06）    │
                 └──────────── 失败且次数用完 ──▶ 面板「再来一次」点击 ──────┘
                                     最后一关通过 ──▶ ALL_CLEAR ──点击──▶ HOME
```

```ts
// 测试脚本（挂在任意节点上，拿到 Boot 组件即可）
const boot = node.getComponent('Boot') as Boot;
boot.debugJump('PLAY', 5);        // 直接进第 5 关跑动（不写存档、不校验解锁）
boot.debugJump('JUDGED', 1);      // 直接出第 1 关的评级面板（用 core 的 perfectMs 判一次）
boot.debugJump('LEVEL_CLEAR', 3); // 过关页
boot.debugJump('ALL_CLEAR', 15);  // 全通页
boot.debugJump('HOME', 1);        // 首页
boot.currentState();              // 断言当前状态
```

**验收用例（建议直接进 BUG 清单）**

| 用例 | 步骤 | 期望 |
| --- | --- | --- |
| 连点只认一次 | PLAY 中 0.2s 内点 5 次 | 只出 1 次判定，剩余次数只 −1，第二次起无任何反应 |
| 结算中点击 | JUDGED 出现后 900ms 内连点 | 不跳关、不改数值（`feedbackMs < resultHold` 直接 return） |
| 暂停中点击 | JUDGED 内任意点击 | 物体位置不再变化（`clock.setPaused(true)`） |
| 按早/按晚文案 | `debugJump('JUDGED', 1)` | 面板出现「按早了/按晚了 N ms（M°）」，模板来自 `TIMING_TEXT` |
| 进度存档 | 过 L1 后杀进程重进 | 首页点开始直接进 L2 |
| 双物体 | `debugJump('PLAY', 10)` | 两条车道各一个绿框、各一个物体，同一帧判定 |
| 空配置 | 删掉 levels.json 再运行 | 面板显示「配置读取失败…」，不崩、不黑屏 |

## 5. 性能预算（本机无 profiler，数值为预算与估算，实测待编辑器）

| 项 | 预算 | 本实现的账 |
| --- | --- | --- |
| 判定单次 | **≤ 0.2ms**（红线） | 全部在 core（多边形精算）。客户端只在按下时调用 1 次，路径上无任何额外几何计算 |
| 单帧粒子 | **≤ 120**（红线） | v0.1 **不使用粒子系统**：闪白是 1 个全屏 Graphics 矩形 + `UIOpacity`，热力图是 2 层 Graphics，绿框每次进场画 1 次。粒子数 = 0 |
| 每帧重建路径数 | 每个运动物体 ≤ 48 `lineTo` | 2 物体 = ≤ 96 `lineTo`/帧（lead 定的方案：静止绿框只画一次，物体每帧 `clear()` 重画）。顶点坐标**开机时预算好**，逐帧只做 moveTo/lineTo |
| update 内分配 | 0 B 目标 | `Boot.update` / `LevelRunner.update` / `Mover.applyPose` 不 `new`、不拼字符串、无链式调用；HUD 全字段有值缓存 |
| Update 内 core 对象分配 | 已知 1 项（见 R-11） | 每帧 `poseAt()` 会返回 2 个 `Pose` 对象（core 侧分配）。若实测 GC 抖动，让 core 加 `poseInto(out)` 即可，客户端调用点只有 1 处 |
| Draw call 估算 | ≤ 12 | 背景 1（24 段渐变在同一个 Graphics 内合批）· 绿框 1 · 物体 2 · 热力图 2 · 闪白 1 · HUD 文字 4 · 按钮 2 · 面板 1 |
| 首帧建树 | < 8ms（估） | 背景 24 段一次性建；之后不再触碰（`BG_BANDS` 调成 1 即退化成纯色） |

### 6.3 我明确**没做**的事（避免误以为漏了）

- 没做音效（`assets/audio/` 空着）、没做分享/录屏、没做埋点、没做三档画质 —— 都不在本迭代垂直切片内。
- 没画 `ShapeDef.details`（装饰细节）：`details` 只用于美术化版本，v0.1 只画主轮廓，避免"看上去有细节但不是判定轮廓"造成误读。
- 没做无尽模式、没做双轮廓异形（关卡 10/15 的 dual 已支持：`buildLevel` 返回 2 个 mover）。
- **没给可玩区加 `Mask` 裁剪**：物体是从左右两侧出画的（`x` 从 -180 到 900），垂直方向由 core 的路径保证；
  如果美术要求物体进 HUD 区域就裁掉，给 `ObjectLayer` 加一个 `Mask` 组件即可（单点改动，不在本版范围内因为 `Mask` API 未验证）。

## 8. 体检状态（lead 代跑：**10/10 全过**）

**本会话 shell 不可用**：`pwsh -Command "echo probe-ok"`（不带 `sandbox_permissions`）返回 `(no output) [exit code: 3221225794]`（0xC0000142，进程启动阶段即失败），因此语法体检**由 lead 代跑**。命令（逐文件）：

```
& "C:\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe" -e "const fs=require('fs'),{stripTypeScriptTypes}=require('node:module');const p=process.argv[1];try{stripTypeScriptTypes(fs.readFileSync(p,'utf8'),{mode:'strip'});console.log('OK',p)}catch(e){console.log('FAIL',p,e.message)}" <file>
```
