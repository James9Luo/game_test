两张参考图都在 02_美术源文件/参考图/。左边是轮廓插画，右边是分片结构——两件都是"平涂 + 结构线"，没有渐变、没有投影、没有高光。

02从参考图提炼的 10 条风格规则

这 10 条是可以量化的，交稿自检按它逐条打勾。核心一句：质感来自"分色块 + 结构线"，不来自渐变。

#规则量化口径（size 250 的道具）为什么
1纯平涂同一色块内 0 渐变、0 渐变带；全件最多 3 种色风格圣经 §6 relax：不要"亮与快"；绿框必须是全场最亮
2单描边（不是双描边）1 笔，3.5–4.5px @1x（长边 1.6–1.8%），色 = 主色压暗，不用纯黑参考图是干净的插画线；现在的"墨外边 4px + 主描边 2px"叠成双线，偏重
3结构线宽 2–2.5px（描边的 55–65%），色 = 该色块同色相压暗 30%羽毛线 / 球瓣接缝 / 篮纹，全是"同色系深一档"，不引入新色
4分色块每件 1–2 个副色块（腹部 / 翅根 / 高光面）；副块面积 ≤ 剪影 25%这是"体积感"的主要来源：一个暗块就够，多了会花
5深色系描边不纯黑描边取主色压暗两档，允许偏冷或偏暖（棕 / 藏蓝）纯黑会脏；参考图的深棕、深藏蓝都带色
6极简五官眼 = 1 个实心椭圆，半径 ≤ 长边 3%；不画眼白高光参考图的眼睛就是一个点；高光点会被误读成"另一个零件"
7有机剪影曲线为主，直线段 ≤ 总边数的 35%；对称形必须留 1 处不对称参考图的手感来自弧线；几何直边会读成"图标"
8点缀色单点使用跳出色族的小面积色（蓝眼、红旗）≤ 面积 3%，且全件只 1 处保住 5 色族纪律（风格圣经 §2.3），又不让道具太素
9结构线可数每件 4–10 条结构线，方向统一（沿长轴或沿曲面）太多会碎；4–10 条正好是"插画感"的密度
10剪影优先缩到 96px 宽转灰度仍能认出是什么（v0.7 可辨识门槛）判定靠轮廓；轮廓一糊，玩法就废

对照上一版方案（已否决）：渐变体积光 / 边缘光 / 高光斑 / additive 全部作废 —— 它们违反规则 1、4、6，且会把绿框的注意力抢走。 新的做法是：把"平涂 + 双描边"换成"平涂 + 单描边 + 分色块 + 结构线"，并且全部落在 details 里。

05几何自检（新样张）

口径与 03_交付素材/check_shapes.py 一致：顶点数 12–48 · 长边 = 1（±2%）· 形心 ≈ 原点（≤0.05）· 简单多边形不自交 · rot30 < 92%（栅格采样）。

id名称顶点数长边形心偏移面积占比自交对数rot30判定

k（命中窗口系数）本机测不了：check_shapes.py 依赖 Python + Pillow，本机 python / node 均不在 PATH。 按项目纪律，k 必须由主策划 tool 实测，此处只做几何与 rot30 自检。

06落地口径

数据层

  • 零契约改动：复用 details 的 poly / line / circle，颜色加 #RRGGBBAA
  • 描边参数从 shape.stroke 取（已是主色压暗两档），宽度改渲染层，不改数据
  • 眼睛 / 小配件走 circle，半径归一化
  • 分色块用 poly，顶点必须落在主轮廓内

渲染层（两处）

  • 原型 drawObject()：去掉"墨外边 + 主描边"双线，改单描边 3.5–4.5px；补 details 绘制（原型已有，需调整顺序为 主体 → 分色块 → 结构线 → 描边）
  • 引擎 Mover.ts：目前完全不画 details，要补 line / poly / circle 三支（约 30 行）
  • 去掉双描边会让深底下的剪影变轻 → 用描边加粗到 4px补，不要加外发光

资产与排期

  • 36 件现有道具：每件补 1 个分色块 + 4–8 条结构线（从 2.8 条提到 6–10 条）
  • 新道具：先出 飞鸟 + 热气球两件样张，验证风格与 k，再批量
  • 每件出图后跑 check_shapes.py + 接触表
  • 验收：判定逐位不变 + 缩略可辨 + 三场景目视
