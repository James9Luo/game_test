## 0. 结论先行（四条）

1. **36 个道具"看着平"的根因不是画得不好，是渲染管线里没有光。** `drawObject()` 只做四步：深墨外边 → 主体平涂 → 主描边 → 装饰（平均 **2.8 条**/件）。一块纯色 + 一圈描边 = 贴纸。
2. **质感必须落在物体自身内部**，不能加投影、不能加光晕——绿框是唯一锚点、物体在飞不落地、热力图要叠在物体上。落点是 **L1 体积 + L2 边缘光 + L3 材质纹理**。
3. **落地不碰判定、不碰引擎契约**：质感全部写进 `details`（复用现有 `poly / line / circle` 三种 kind），只给颜色加 **alpha 位**（`#RRGGBBAA`）。`pts` 一个字节不动 → 绿框重合判定逐位不变。
4. **新道具 30 个候选（5 类 × 6）**，出口是**图鉴 + 助眠池**，**不动 60 关关卡表**（D-087 换形进关已作废）。批次：P1 12 个 / P2 12 个 / P3 6 个。唯一连带影响：`collection.json` 稀有池 15 → 45，`thresholds` 需重标（要 node）。

## 1. 现状诊断

### 1.1 绘制顺序（代码级，非印象）

原型 `原型/_src/game.js:2303 drawObject()`：

| 步 | 动作 | 参数 | 视觉后果 |
| --- | --- | --- | --- |
| ① | 深墨外描边 | `COL.ink`，`lineWidth = 2/k × 2` | 只负责把物体从深底里"抠"出来 |
| ② | 主体填充 | `shape.fill` **平涂** | 纯色，无明暗 → 体积感为 0 |
| ③ | 主描边 | `shape.stroke`，2px | 压暗两档的同色系，保剪影 |
| ④ | 装饰 details | `line / circle / poly` | 0–4 条（36 件合计 100 条，**平均 2.8**） |

引擎 `assets/scripts/gameplay/Mover.ts:75-107`：

| 步 | 动作 | 与原型的差距 |
| --- | --- | --- |
| ① | `fillColor` + `strokeColor` + 一次 `fill()/stroke()` | **没有 details**、**没有墨外边** → 引擎版比原型还平 |

> **技术债 1（必须记）**：Cocos 侧至今不画 `details`。这意味着现在"2.8 条装饰"只有原型有，引擎里一件都没有。做质感之前，**先补引擎的 details 渲染**（约 30 行，见 §3.2），否则美术画了引擎也不显示。

### 1.2 三个可量化的数

| 数 | 值 | 出处 |
| --- | --- | --- |
| 道具总数 | **36**（主线池 21 + 稀有池 15） | `collection.json` |
| 平均装饰条数 | **2.8 条/件**（0–4 条） | 遍历 `shapes.json` |
| 渐变 / 阴影 / 高光层 | **0** | 两条渲染管线都没有 |

### 1.3 为什么不能靠"加投影、加光晕"解决

| 约束 | 出处 | 结论 |
| --- | --- | --- |
| 绿框描边 L=80%，是全场唯一锚点 | 风格圣经 §3 | 任何比它亮的元素都会抢焦点 → 禁止物体发光 |
| 场景层亮度预算 +18pp | 风格圣经 §7.2 | 物体自身明暗不占场景预算，但局部提亮仍受 §6.1 约束 |
| 物体在飞，不落地 | 玩法设定 | 局内加接地阴影 = 给空中物体造地面，读作 bug |
| 热力图三区叠在物体上 | 风格圣经 §5.1 | 物体自身明暗太碎会吃掉"哪里歪了"的判定信息 |
| 柔光呼吸是唯一允许的亮层 | 风格圣经 §6.2 | 已占掉"瞬时提亮"的名额 |

### 1.4 结论

**质感的落点是"物体自身内部"**——顶光体积 + 边缘光 + 材质纹理。视觉上从"贴纸"变成"物件"，判定上什么都不变。

## 2. 质感方案：四层模型

### 2.1 L1 · 体积（让一块平涂变成一个"体"）

| 层 | 做法 | 参数 | 为什么这么定 |
| --- | --- | --- | --- |
| 顶光 | 物体上缘提亮 | `rgba(255,255,255,α≤0.20)`，source-over，**禁止 additive / lighter** | additive 会与绿框外发光叠加爆亮（§6.2 禁令） |
| 底调 | 物体下缘压暗 | `rgba(0,0,0,α≤0.26)` | 顶亮底暗是二维里最省的体积暗示 |
| 内阴影 | 右下轮廓内侧一圈暗带 | 宽 2–4px，α ≤ 0.38 | 把边缘"压"进背景，物体会沉下去而不是浮着 |

### 2.2 L2 · 边缘光（把剪影从背景里抠出来）

- 位置：**左上 1/3 弧段**（光源假设恒定在左上）。
- 做法：一条 `line`（w 2–3px，α ≤ 0.5，色 = `fill` 提亮 45%），沿轮廓走。
- **真正的用处在亮底**：`noon_window` 背景 L=94.6%，绿框在亮底只有 1.75:1（美术_轮廓规格 §3.3），边缘光是把物体从底色里救回来的唯一手段。
- 禁：不许整圈描边（那会变成"发光"），不许超过 1/3 弧长。

### 2.3 L3 · 材质纹理（一件道具 = 一种材料）

> 这是"道具库"从**器物**变成**物品**的关键层。同一个圆柱，是金属、是陶、是木，差别全在这 2–6 条纹理。

| 材质 | 识别色 | 配方（画什么） | 条数 | 禁 |
| --- | --- | --- | --- | --- |
| 金属 | `#C9D4E3` / `#A8B4C8` | 1 条竖向反光带（提亮 55%，α .22）+ 1 条横向暗带（α .14）+ 2 颗铆钉点 | 3–4 | 不许用纯白高光 |
| 陶瓷 | `#F2F2F7` | 左上高光椭圆（α .30，扁 3:1）+ 底部暗弧 1 条 | 2 | 高光不许成圆点（会读成眼睛） |
| 玻璃 | `#A8C8E8` | 内层半透明面（α .22）+ 1 条竖高光 + 1 条底缘亮线 | 3 | 不许整件透明 |
| 木 | `#C8B49A` | 2–3 条弯纹（α .28，深同色系）+ 1 个端面深块 | 3–4 | 不许超 4 条（会脏） |
| 织物 / 皮 | `#FF9FB2` / `#C3B1E1` | 2–4 条短褶皱线（长短不一）+ 1–2 条虚线缝线 | 3–5 | 不许平行等距（机械感） |
| 植物 | `#9C9BE8` / `#8FD3F5` | 主脉 1 条 + 侧脉 4 条 + 边缘刺点 3–5 颗 | 6–8 | 叶脉不许出主轮廓 |
| 食物 | `#F5C062` / `#FFE066` | 表面斑点 4–8 颗 + 顶部高光 1 块 + 层次分界线 | 6–9 | 斑点不许等距 |
| 纸 | `#C3B1E1` | 页边平行线 3–5 条 + 封面分割线 1 条 | 4–6 | 线不许超 1.5px |
| 金属漆 / 塑料 | `#8FD3F5` / `#9C9BE8` | 1 条弧形高光带（沿最长边）+ 1 条分模线 | 2 | 高光带不许过轮廓中线 |

### 2.4 L4 · 接地（只用在静物场景）

- 用在：**图鉴页 / 结算面板 / 首页静物**；**局内不加**（物体在飞）。
- 做法：接触阴影椭圆（α ≤ 0.25）+ 环境反光。
- 价值：图鉴 36 格从"图标"变成"陈列品"；未解锁的灰剪影也有实体感。

### 2.5 三档强度（对应三档画质）

| 档 | 保留层 | 用在哪 |
| --- | --- | --- |
| 轻 | L1 顶光 + 主描边 | 低画质机（`settings` 画质档） |
| 中（**默认**） | L1 + L2 + L3（材质纹理减半） | 局内正常玩法 |
| 重 | L1 + L2 + L3 全量 + L4 接地 | 图鉴页 / 结算面板 |

### 2.6 质感规范 12 条（美术交稿自检 / 程序落地对照）

| # | 规范 | 为什么 |
| --- | --- | --- |
| ① | 判定零影响：质感层只进 `details`，`pts` 一个字节不动 | 绿框重合判定必须逐位不变 |
| ② | 描边不被吃掉：细节内缩 ≥ 1px，主描边 2px 永远在最上层 | 描边是剪影命脉 |
| ③ | 线宽下限：装饰线 ≥ 2px @1x | 低于 2px 在 720 宽屏上直接消失 |
| ④ | 明度上限：高光叠加后局部 L ≤ fill 原 L + 8pp，且 ≤ 92% | 风格圣经 §6.1 |
| ⑤ | 锚点不被抢：物体任何像素不得比绿框描边（L 80%）更亮 | 琥珀亮档 `#FFE066`（L 87%）是已记档的既有例外 |
| ⑥ | 绿框独占：新增色不得进入 mint 色相 ±20° 区间 | 否则读成"这也是目标" |
| ⑦ | 细节密度：6–10 条/件（现状 2.8）；装饰总面积 ≤ 剪影 12% | 少则平，多则碎 |
| ⑧ | 剪影优先：缩到 96px 宽转灰度仍能认出是什么 | v0.7 §2.3 可辨识门槛 |
| ⑨ | 热力图可读：物体自身明暗对比 ≤ 内部 30% 相对差 | 三区叠加后仍要分得开 |
| ⑩ | 材质唯一：1 主材质 + ≤1 副材质 | 禁止混搭出"金属木纹" |
| ⑪ | 亮底可读：noon 场景下物体与背景对比 ≥ 1.7:1 | 靠暗描边 + 边缘光 |
| ⑫ | 落地形态：纹理必须能用 poly / line / circle 画出来 | 不许依赖渐变贴图、不许引外部资源（D-029） |

## 3. 落地实现：两个引擎各加什么

### 3.1 数据层（**零契约改动**）

`shapes.json` 的 `details` 三种 kind 全部复用，只给 `color` 加 alpha 位：

```jsonc
"details": [
  { "k": "poly",   "pts": [...], "color": "#0A122A61" },   // 预烘焙暗面
  { "k": "line",   "pts": [...], "w": 3, "color": "#FFFFFFB3" }, // 边缘光
  { "k": "circle", "c": {...}, "r": 0.05, "filled": true, "color": "#FFFFFF4D" } // 高光斑
]
```

- 原型 canvas：`ctx.fillStyle = '#RRGGBBAA'` **原生支持** → 零改动。
- 引擎 `Theme.hexColor()` **已经支持 `#RRGGBBAA`**（`assets/scripts/ui/Theme.ts:46`）→ 零改动。
- ⚠️ `Shapes.ts` 的 `HEX6` 校验只管 `fill` / `stroke`，**不管 details 的 color** → 不用改校验器。
- ⚠️ `Types.ts` 的 `ShapeDetail` 类型里 `color: string`，**不用改**（还是 string）。

> 结论：**美术多画几条 details + 程序在引擎里把 details 画出来**，就是全部。

### 3.2 引擎侧要补的那一段（程序任务）

`assets/scripts/gameplay/Mover.ts` 现在是"一次 `fill()` + 一次 `stroke()`"。要补：

1. 画 `details`：`line` → `moveTo/lineTo + stroke`（`lineWidth` 要除以缩放倍率，**w 单位是 1x 设计像素**）；`poly` → `close() + fill`；`circle` → `arc` + `fill`/`stroke`。
2. 颜色：`hexColor(d.color)` —— 已支持 AA。
3. 层次顺序：**先主体 fill → 再 details → 最后主描边**（描边压在最上）。
4. 需要验证： Cocos `Graphics.fillColor` 的 **alpha 是否真的生效**（顶点色带 alpha，需真机核）。若不生效，退路 = 把明暗面**预烘焙成不透明多边形**（用同色系明暗档，不用 alpha）。

### 3.3 实时渐变 vs 预烘焙（取舍）

| 方案 | 原型 | 引擎 | 视觉 | 结论 |
| --- | --- | --- | --- | --- |
| 实时渐变 + clip | 一行 `createLinearGradient` + `clip()` | **Graphics 无 clip、无渐变** | 最好 | 只能做原型预览 |
| 预烘焙明暗多边形 | 同上（照画） | 照画即可 | 略平但一致 | **以它为准** |
| 引擎侧用多个子路径分色 | 支持 | 支持（多段 path） | 中 | 兜底 |

> **定调：以"预烘焙明暗多边形 + 边缘光"为交付标准**，两引擎逐像素一致；原型里额外叠一层实时渐变作为"上限参考"（提案页 §03 的 Before-After 就是这一版）。
