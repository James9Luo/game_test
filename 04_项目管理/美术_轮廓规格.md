## 2. 难度是怎么来的

### 2.1 一条量化口径

转 θ 角时，轮廓上离形心 r 的点会错位 ≈ 2·r·sin(θ/2)。所以**掉分速度由「质量离形心多远、边界有多不平滑」决定**，不是单纯由长宽比决定。用四个可测量指标描述：

| 指标 | 含义 | 用途 |
| --- | --- | --- |
| `rot30` | 转 30° 后还剩多少重合率 | 硬指标：**必须 < 92%**，否则「歪一点也高分」 |
| `angle80` / `angle60` | 重合率掉到 80% / 60% 所需角度 | 与主策划给的矩形基准表直接对照 |
| `aEquiv` | 等效矩形长宽比 = 58.6/(angle80+3.8) | 把任意形状折算成「相当于几比几的矩形」，跨形状可比 |
| **`k2`** | **2 圈时的命中窗口 / 周期** | **排序指标**（D-135）：玩家感受到的窗口宽窄；**难度门禁 = 窗口毫秒守恒**，k 参考带 **0.013–0.080**（旧 0.020–0.047 已废） |

`k2` 怎么来的（与 `tools/export_levels.mjs` 的 `windowMetrics` 同源）：窗口 = 重合率 ≥ passRate(60%) 的时间段长度。
以 perfectMs 为中心，物体同时在做「平移 + 自转」，两者都随 Δt 线性增长：

```
v = 1080/cycle (px/ms, h_line 长 1080)      ω = turns·360/cycle (°/ms)
pose(Δt) = 自转 ω·Δt + 平移 v·Δt   →   二分到 overlap < 60% 的早/晚边界
k = (|early| + late) / cycle
```

**实测 k 里位置项和转角项都在起作用，所以不能只用「rotation-only」的闭式解**：同一个闭式解会给出 cup 0.12、toilet 0.13（都"合格"），而实测是 0.031 / 0.028 —— 差 4 倍。这也是为什么：
- 细长形（banana/wrench）由**转角项**主导 → 加厚/加长就变宽容；
- 矮胖形（duck/tv/burger）由**位置项**主导 → 只有「削掉一块 / 甩出一条」才救得回来，单纯换颜色没用。

> 纪律：**形状敏感的最终裁决权在主策划的 tool**。自算 k2 只用于形状之间排序与预警（运行时校准 K_SCALE=0.486）；**k 不作门禁**（D-135），验收看窗口毫秒。

**为什么 aEquiv 只能当参考**：主策划实测 car 的 aEquiv 2.74（看起来够严），但 k2 = 0.047（很宽容）——因为车身长、位移容错大。**一律以 k2 为准。**

### 2.2 三类难度来源（本迭代实际用到的）

| 类型 | 机制 | 本项目里的形状 |
| --- | --- | --- |
| **细长** | 长轴方向一偏，整条边扫出去 | 扳手 3.14、吉他 2.91、拖鞋 2.67、火箭 2.56、锤子 2.50 |
| **凹形** | 凹口/凸起旋转后直接错位到另一块区域，面积损失是「整块」而非「边缘」 | 吉他腰（凹）、扳手钳口（V 缝）、拖鞋带梁（拱）、章鱼触手间谷、汉堡波浪边、电视机脚 |
| **离心质量** | 远端特征（嘴、尾、耳、鳍、拉环）转过 10° 就走位，而它的面积占比不小 | 鸭嘴/鸭尾、猫耳/猫尾、火箭尾翼、可乐拉环、保温杯凸起 |

### 2.3 为什么不做「一律 ≥2.2:1」（已与主策划确认，2026-10-18）

圆和正方形 rot30 = 100% / 84.5% —— 怎么转都高分，这是**必须排除**的那一类（本套 **36 个**形状 rot30 全部远低于 92%）。
但反过来，把鸭子做成 2.2:1 就不是鸭子了。**主策划拍板：接受 aEquiv 口径，动物/器物比例保留**，难度改由 `k2` 收口。所以本表把物理长宽比与 aEquiv 并列：**物理比例负责辨识度，k2 负责难度**。
仍不达标的形状（当前：banana / burger / tv / octopus）按 k2 单点返工，返工手段见 §6 与各形状备注。

#### 3.5.4 worstAddPct 复算（背景 L → 叠加后 L → Δpp）

公式（`风格圣经` §6.1 / §7.2）：

```
L = (0.2126·R + 0.7152·G + 0.0722·B) / 255 × 100      # 相对亮度，纯白 = 100%
source-over 在通道上是线性的，故 L 可直接合成：L_out = α·L_src + (1−α)·L_bg
预算：最坏点 L ≤ 背景 L + 18 个百分点（18 是绝对 pp，不是相对百分比）
最坏点 = 各层 α 峰值在同一像素重叠处；背景取渐变**更亮的一端**（与 night 13.4 同口径）
```

**表 1 · 色值 → 相对亮度 L**

| 色 | RGB | 计算 | L |
| --- | --- | --- | --- |
| bg 顶 `#141A24` | 20, 26, 36 | (0.2126×20 + 0.7152×26 + 0.0722×36)/255 = (4.2520+18.5952+2.5992)/255 = 25.4464/255 | **9.98%** |
| bg 底 `#0E1420` | 14, 20, 32 | (2.9764+14.3040+2.3104)/255 = 19.5908/255 | 7.68% |
| 剪影 `#8FA6C4` | 143, 166, 196 | (30.4018+118.7232+14.1512)/255 = 163.2762/255 | **64.03%** |
| 尘点 `#E8F1FF` | 232, 241, 255 | (49.3232+172.3632+18.4110)/255 = 240.0974/255 | **94.16%** |

**表 2 · 逐层合成（都叠在顶色 9.98% 上）**

| 步 | 计算 | 结果 L | Δpp |
| --- | --- | --- | --- |
| ① 剪影单层 α0.07 | 0.07×64.03 + 0.93×9.98 = 4.4821 + 9.2804 = 13.7625 | **13.76%** | +3.78 |
| ② 尘点单层 α0.06 | 0.06×94.16 + 0.94×9.98 = 5.6493 + 9.3802 = 15.0295 | 15.03% | +5.05（= 原记录 5.1，口径校验通过 ✓） |
| ③ 最坏点：尘点叠在剪影上 | 0.06×94.16 + 0.94×13.76 = 5.6493 + 12.9366 = 18.5859 | **18.59%** | 18.59 − 9.98 = **+8.61 → 8.6** |
| ③′ 另一画序：剪影叠在尘点上 | 0.07×64.03 + 0.93×15.03 = 4.4821 + 13.9774 = 18.4595 | 18.46% | +8.48（更松，不作数） |

**结论：`worstAddPct` = max(③, ③′) = 8.61 → 记 8.6**，≤18 硬线上限 ✓，≤9 目标 ✓。
另两条预算同时过：单层叠加后最亮 18.59% ≪ 绿框描边 L 80%（余量 61.4pp，规则「任何元素不得比绿框更亮」✓）；全程 source-over，无 additive ✓。

**局部梯度复核**（台灯在画面下方，那里底色更暗，不能只算顶色）：`yPct 0.789` 处 bg L = 9.98 + (7.68 − 9.98)×0.789 = **8.17%**

#### 3.5.5 时序：可见段与完全不可见段


#### 3.5.7 需程序支持（**明确标注：本层今天跑不起来**）

`k:"silhouette"` 是**第七种图层类型**，`原型/_src/game.js` 的 `drawSceneLayers()` 里**没有这个分支**。当前行为：落到 `else if` 链之外 → **静默不画、不崩**（这也是它能先落 JSON 的原因）。程序次日要补：

```js
else if (L.k === 'silhouette') {                                    // 1 新 k：具名静态剪影（需程序支持）
    var age = nowMs() - (L.phaseBase === 'levelStart' ? (app.sceneAppliedAtMs || 0) : 0);
    var v = (((age % per) + per) % per);                            // 2 周期内位置 0..periodMs
    var a2 = silAlpha(v, L);                                        // 3 0..fadeIn 升 / 保持 / 末段降 / 其余 0（easeInOutSine）
    if (a2 > 0.001) fillSilhouette(L, a2);                          // 4 一个 path（poly+rect+ellipse, nonzero）一次填充，无描边无模糊
}
```

两条辅助契约（照抄即可，别自己改口径）：

| 函数 | 规格 |
| --- | --- |
| `silAlpha(v, L)` | `holdMs = visibleMs − fadeInMs − fadeOutMs`（=4200）。`v < fadeInMs → easeInOutSine(v/fadeInMs)`；`v < fadeInMs+holdMs → 1`；`v < visibleMs → easeInOutSine((visibleMs−v)/fadeOutMs)`；`v < periodMs → 0` |
| `fillSilhouette(L, a)` | 包围盒：`cx = xPct*W, cy = yPct*H, w = wPx, h = hPx`；图元：`px = cx − w/2 + u*w`、`py = cy − h/2 + v*h`；`ctx.fillStyle = 'rgba(143,166,196,' + a + ')'`（**α 只乘一次**，禁止再叠 `L.alpha`） |

界面/数据契约三条：① `app.sceneAppliedAtMs` 必须在 `applySceneForLevel()` 里写值，否则 `phaseBase` 失效 → 退回墙钟 → C1-a 截图不可复现；② `drawSceneLayers()` 的层循环上限是 **3**（`i < 3`），minimal 现在是 2 层，**没有余量给第三层**，再加层必须先改上限并重新过预算；③ 本层 `n=1`、`driftPx=0`，程序不许拿这两个字段做任何变化。

## 7. 变更纪律

1. 改 `pts` → 必须重跑 `check_shapes.py`，`ALL GREEN`（或只剩已拍板接受的 NOTE）才能提交；同时把 §1 表里的顶点数/长宽比同步更新。
   **改法走补丁而不是整文件重写**：把要改的形状写进 `02_美术源文件/shapes_src/redesign_vN.json`，然后
   `python 03_交付素材/check_shapes.py --merge 02_美术源文件/shapes_src/redesign_vN.json --fix`。
   `--merge` 按 id 覆盖、未知 id 直接 FAIL —— 这条就是为了守住「15 个 id 不许增删」的契约（v1 曾因整文件重写漏掉 `can_cola`，让 L5 崩过一次）。
2. 改 `size` 或 `id` → **先发消息给主策划**（牵动 `levels.json` 与判定），再改。`size` 属规格（**240–330**，特批件见道具总表），不是调难度的旋钮。
3. 改 `details` → 只影响观感，不动判定；但必须重跑 `render_preview.py` 目视确认没画出轮廓外。
4. 换皮（同一轮廓不同外观）：只换 `fill`/`stroke`/`details`，`pts` 一个字都不许改——判定口径不能因皮肤而变。
5. 绿框描边宽度、热力图三色、`TARGET_*` 坐标均属玩法信息，改动需主策划签字（见 `02_美术源文件/风格圣经.md` §3）。
6. **本版（v3）已冻结**：`shapes.json` 只能由主策划发起变更；任何形状改动都会让 §5.3 的 k 表失效，必须重跑 `check_shapes.py` + 主策划的 k 工具 + `tools/export_levels.mjs` 三件套。
