# 经验教训 · 2026-10-22 · v11 道具视觉重制（36 件全量换形）

> 范围：D-110 ~ D-126。从「参考样张」到「36 件进局内 + 图鉴贴图」的全过程。
> 用途：这不是流水账，是**下次换道具/换美术风格时，能省掉一整轮返工的 14 条规则**。
> 每条都写成「现象 → 根因 → 证据 → 以后怎么做」，没证据的猜测一律不进本文。

## 二、14 条规则

### A. 素材来源

**A1. 生成图只能当 look-dev，不能当资产。**
- 现象：参考样张的作者说「用 PowerShell + .NET 画的」。
- 根因：不是画的，是**模型生成 + .NET 后处理**（抠底/归一/拼版/量亮度）。
- 证据：`gen_batch.json` 是英文提示词；`fetch_raw.ps1` 调 `mcode-tools get_asset_url <node_id>`；成品 PNG 内嵌 C2PA `trainedAlgorithmicMedia` + `Credit="Made with Google AI"`。
- 规则：生成图进 `02_美术源文件/`，进游戏的永远是多边形数据；不要把位图塞 `assets/`。

**A2. 提示词模板要写“可判定的约束”。**
- 现象：对方提示词写了「2px 描边」「不许渐变」，出图仍有 5–13% 像素超 78% 亮度。
- 根因：模型不听数值指令，只吃“结构描述”。
- 规则：模板里写**相对量**（描边 ≈ 长边 1.5–2%、最细处 ≥ 宽 6%、单一闭合剪影）而不是绝对 px；验收靠我方量测，不靠提示词。

### B. 判定口径（最不能动的一层）

**B1. 判定必须吃解析几何，不能吃像素。**
- 现象：想让局内直接用贴图判定。
- 根因：命中窗口 / 神级窗口都是**对 pct(t) 二分反解**出来的，必须有连续函数；像素采样在 250px 物体上 1px 误差 ≈ 1.5% 面积，神级 95% 的边界直接掉档。
- 规则：**判定用多边形，显示用贴图**（D-125）。绿框与判定同源，永不与判定脱钩。

**B2. 顶点数不是难度杠杆——这条被实测推翻过一次。**
- 现象：一直按「12–48 顶点，48 以上判定开销翻倍」守。
- 证据：同一件 44 → 80 顶点，k 只变 **0.10–0.30%**（窗口 +0.3–0.6ms），自交 0，rot30 不动。
- 规则：顶点上限是**可读性与自交**的门槛，不是难度门槛；实测后放宽到 80（D-119）。**任何“我们一直这么干”的常数，都要找一次实测依据。**

### C. 描样算法（这轮踩得最狠）

**C1. DP 删点会在细长件上制造自交。**
- 现象：龙虾、飞龙、扳手多次 `自交 1`。
- 根因：DP 允许“跳点连线”，细长肢体上跳点就会跨过对边。
- 规则：细长/带肢体件改用**弧长均匀重采样**（`trace.resample_closed`），保序、天然不自交。

**C2. 只描“最大连通分量”＝丢部件。**
- 现象：L22/23/28/31/33/34/37/38/39 的绿框少了书页、冰淇淋球、螃蟹腿。
- 根因：这批贴图里**分离部件占比大**，取最大分量就把它们扔了。
- 证据：重描前书是「方块」、冰淇淋是「圆锥」；重描后长宽比与贴图差 ≤0.02（书本 1.31 vs 1.32、冰淇淋 0.45 vs 0.44）。
- 规则：轮廓必须覆盖 **alpha 的全部有效像素**；管线固定为「膨胀 5px → 取最大连通 → **填洞** → 沿边串环 → 弧长重采样 ≤80」。

**C3. 区域有洞，单环串边必自交。**
- 现象：飞龙填洞前重采样仍自交。
- 根因：翅膀与身体之间的空洞让一个环在内外边界间跳。
- 规则：串边前先**填洞**（从 bbox 边界泛洪，没泛到的就是洞）。

**C4. 采样坐标必须 bbox 对齐。**
- 现象：汽车车窗块被染成车身色 → 整辆「一团蓝」；鸭子发褐。
- 根因：形状坐标是「形心 + 长边=1」，贴图是「紧裁 bbox」，两者原点不同。
- 规则：任何“按贴图取色”的步骤都要先做**形状 bbox ↔ 贴图 bbox 的线性映射**；取色失败时先怀疑映射，不要怀疑顶点数。

**C5. 底色不要取 bbox 中心。**
- 现象：吉他整把琴发土褐。
- 根因：bbox 中心正好落在**音孔**（深色）上；另一个坑是大块「中间调」色块（L 0.42–0.58）把画面糊成泥。
- 规则：底色取**贴图出现最多的颜色**；丢掉「面积大且 L 在 0.42–0.58」的中间调块。

### D. 尺寸与节奏

**D1. 尺寸/车道缩放会改变难度。**
- 现象：吉他 size 276→330，L7 窗口漂移 **45.6%**。
- 根因：物体面积被归一化到 targetArea，车道缩放也参与；窗口随之变。
- 规则：**任何 size / 车道 / 形状改动，必须跑 `tools/refit_cycles.mjs --apply`**；机制关还要守 S11（不许比同季上一关更快）。

**D2. 「统一面积」式全局缩放会伤到没被投诉的件。**
- 现象：把 36 件按面积拉平时，书本/电视/可乐罐被缩小 20%，观感变差。
- 规则：尺寸策略用**只放大、不缩小**，且只对用户点名的件生效（吉他/扳手/锤子）。

**D3. 用户说「小」有三种成因，必须分开处理。**
- 细长件面积小（吉他/扳手）→ 改 `size`
- 双物体车道缩放（L10/L25）→ 改 `TARGET_DUAL.scale`（0.62→0.70）并上移车道中心（330/640→318/618）
- 根本没换新画（锤子）→ 换形
- 规则：收到「小/丑/不一样」先分类，再动手；否则会用错杠杆。

### E. 包体与验收

**E1. 容量红线要按「资产类别」分账。**
- 现象：单文件原型为图鉴贴图连续上调上限 500→600→850→1100KB，每次都要做容量数学。
- 规则：**代码/配置**一张账（原型 700KB 上限），**观赏位图**另一张账（外链，不计入）；贴图永不 base64 内联（D-118）。

**E2. 肉眼验收必须被数字兜底。**
- 这轮真正管用的四个数字：**自交计数 / 长宽比 vs 贴图 / 帧内窗口漂移 / IoU 或面积占比**。
- 规则：每批换完先跑 `shapes_check` + 长宽比体检 + `refit_cycles` + `modes_check`，四绿再喊人看。

**E3. 一次别换太多。**
- 现象：27 件一次过，7 件崩。
- 规则：每批 ≤8 件，批后立即跑客观体检；崩掉的件当天回滚（龙虾/飞龙当时就是回滚 v10）。

## 四、每次换道具的标准动作（贴墙版）

```bash
# 0) 生成图放 02_美术源文件/gen_v11/，提示词按模板（相对量约束）
# 1) 描样：膨胀→最大连通→填洞→串环→弧长重采样≤80；底色=主色；丢中间调
# 2) 客观体检（四绿才继续）
node tools/shapes_check.mjs                      # 自交/顶点/长边
python tools/aspect_audit.py                     # 轮廓 vs 贴图（长宽比 + 面积比）
node tools/refit_cycles.mjs --apply              # 窗口归位
node tools/update_collection_k.mjs --apply       # k/档同步
# 3) 构建与断言
node tools/build_proto.mjs
node tools/modes_check.mjs --write-win-baseline && node tools/modes_check.mjs
node tools/selfcheck_proto.mjs
# 4) 截图对照（贴图 vs 局内）+ 记决策记录
```
