# v0.6 规格 · 双物体错拍（Desync）

> 2026-10-18 · 主策划 · 用户明确要求：双物体错拍做
> 铁律不变：判定=轮廓重合面积、绿框几何静止、一关最多两个难度变量、随机只做速度微扰、单键操作

## 0. 结论先行

**错拍 = 一关要按两次，每次定格"当前最接近绿框的那个物体"，两次都合格才算过关。**

不是"两个物体同时对准"（那会要求两个窗口求交集，实测交集可能为 0，玩法直接失效），也不是"只判主物体"（玩家会觉得按准了不算）。

| 关型 | 物体数 | 按下次数 | 判定 | 过关条件 |
| --- | --- | --- | --- | --- |
| **同步双物体**（现状） | 2 | 1 | 同时取 min(pct) | 一次合格 |
| **错拍双物体**（新） | 2 | **2** | 每次判"最近 C 的那个" | **两次都合格** |

## 1. 字段（2 个，都可缺省）

| 字段 | 范围 | 默认 | 语义 |
| --- | --- | --- | --- |
| `phase_2` | 0–0.5 | 0 | 第二个物体相对第一个的**时间相位偏移**（按周期比例）。0 = 同步（现状），0.5 = 最大错拍 |
| `cycle_2_ms` | 600–4000 | 0 | 第二个物体的周期；**0 表示与第一个相同** |

- `phase_2 = 0` 的关行为必须与现在**逐位相同**（兼容分支，S8 那条纪律）。
- `turns` 两个物体共用；第二个物体沿用同一路径（等距变换）。

## 2. 判定语义

### 2.1 新的判定入口
```
judgeNearest(rt, tMs) → { moverIndex, pct, rating, score, timing }
```
- 计算每个**未定格** mover 在 `tMs` 的姿态与绿框的重合率，取 pct 最大者；
- 与现有 `judge` 的区别：现有 `judge` 返回所有 mover 的 pct（同步关取 min）；`judgeNearest` 只判一个。

### 2.2 过关流程（错拍关）
```
按下 → judgeNearest → 该 mover 标记"已定格"，画面冻结 400ms 展示反馈
     → 若还有未定格 mover：解冻继续，进入第二次定格（计时不停）
     → 若全部已定格：结算本关（各 mover 评级取**最差**者作为本关评级）
```
- **任一 mover 不合格** → 本关按"失败"处理：扣 1 次机会，**两个物体全部重置**（不允许"一个已定格、一个重来"的半成品状态）；
- 每次定格之间**不重置计时**（15 秒倒计时继续走），这是错拍关的真实压力来源。

### 2.3 评级与分数
- 本关评级 = 两次中**较差**的评级（与现有"双物体取最差"口径一致）；
- 分数 = 5 档基础分 × 连击系数（用本关最差评级的基础分算，不叠加两次分数）；
- **热力图**：每次定格时各自画该 mover 的重合热力图（不同时叠两张）。

## 3. 窗口与阶梯

| 概念 | 定义 |
| --- | --- |
| 单 mover 窗口 | 该 mover 自己的 `hitWindow`（独立计算） |
| 关卡窗口（用于阶梯） | 两个 mover 窗口中**较窄者**（玩家必须两边都卡准） |
| 错拍是否增加难度 | 是：`phase_2 > 0` 时第二个 mover 的完美时刻与第一个不同，玩家要在一次失败容错内连续卡两次 |

**phase_2 的取值**：初版只用 **0.35–0.4**（错拍但仍有节奏感）。0.5 会让第二次定格落在第一次失败后的自动重试窗口里，观感混乱，先不用。

## 4. 数据：先做 2 关

| 关 | 现状 | v0.6 | 理由 |
| --- | --- | --- | --- |
| L50（季 4，双物体） | 同步，窗口 45ms | **`phase_2=0.38`** | 季 4 中段，玩家已适应 3 圈 + 惯性 |
| L60（季 4，末关，双物体） | 同步 | **`phase_2=0.4`** | 全季收尾的高压点 |
| L55（季 4，双物体） | 同步 | **不改** | 留一关同步做对照，A/B 能看出错拍到底难多少 |

- 两关都要**重算窗口**（错拍后关卡窗口 = min(两个 mover 窗口)）；
- 若重算后 L50/L60 的窗口不在季 4 阶梯区间（70→18ms）内，先调 `cycle_ms` 而不是改 `phase_2`。

## 5. 验收断言

| # | 项 | 判据 |
| --- | --- | --- |
| S13 | 字段兼容 | `phase_2=0` 的关，其 mover 时间轴与 v0.5 **逐位相同**（`pose(t)` 逐帧相等） |
| S14 | 错拍生效 | `phase_2>0` 的关，两个 mover 的 `perfectMs` 差 ≥ `0.3 × cycleMs`（确实是错拍，不是微扰） |
| S15 | 判定入口一致 | `judgeNearest` 在"两个 mover 同时到达完美点"时返回的 pct，与 `judge` 的 min 相等（同步关不退化） |
| S16 | 两次定格幂等 | 同一 mover 连续 `judgeNearest` 两次，第二次必须返回"已定格"而不得重复计分 |
| S17 | 错拍关的过关条件 | 只定格 1 个 mover 时，关卡状态必须是"未过关"；两个都定格且都合格才 `pass` |
| S18 | **每个 mover 在各自的 `perfectMs` 上完美** | 对每个 mover：`pose(mover, mover.perfectMs)` 落**各自车道中心** ≤0.05px、`pct ≥ 99.9`、且 `hitWindowByMover[m]` 两者都 > 0（错拍关的窗口也必须算得出来） |

> **S18 的口径修正（2026-10-18，被实测逼出来的）**：原写法是"同姿态下换 phase 不改 pct"，**这条是错的**——phase 是时间轴的偏移，改 phase 后同一时刻的**姿态本来就变了**，于是 pct 必然变。正确的不变量是：**每个 mover 在自己的完美时刻上必须完美**。断言只断言不变量，不断言"某个量不该变"。

## 6. 排期与风险

| 阶段 | 内容 | 负责 |
| --- | --- | --- |
| ① 核心层 | `phase_2`/`cycle_2_ms` 字段 + `judgeNearest` + mover 级冻结状态 + `perfectMs` 每个 mover 独立 | 程序 A |
| ② 原型层 | 两次定格流程、HUD「还需定格 N 个」、分次热力图、失败即双重置 | 程序 B |
| ③ 数据 | L50/L60 加 `phase_2`，重算窗口与阶梯 | 主策划 |

**风险**：

| 风险 | 缓解 |
| --- | --- |
| 两次定格让 15 秒倒计时变得过紧（尤其季 4 周期 1.2–1.7s） | 错拍关单独给 **20 秒**（`time_limit_sec` 覆盖），并在 S17 里验"15 秒够不够"用 sim 算通过率 |
| 玩家不知道要按两次 | 首次进入错拍关时显示一行「按两次」提示（仅首次，2 秒淡出）；HUD 用两个小圆点表示"待定格/已定格" |
| 两次定格之间的 400ms 冻结会让第二次时机偏移 | 冻结期间计时暂停（时钟停表），解冻从原时刻继续——**不许让 400ms 反馈吃掉玩家的第二次窗口** |

## 7. 连击保护（D-131，2026-10-22 追加）

**问题**：玩家连点（双击 / 多指连击）时，第二下会被当成"定格第二个"，用错误时机判掉并扣机会 —— 观感是"我明明只按了想按的那一下，却失败了"。

**规则**：第一次定格成功后，**≥ `DESYNC_MIN_SECOND_MS` 才接受第二次按下**；更早的按下 **不判定、不扣机会**，只弹一条「太快了 · 等下一个物体现身」。

**取值 220ms 的依据（实算，不是拍的）**：

| 依据 | 数值 |
| --- | --- |
| 常见双击/连击间隔 | 80–150 ms |
| L50 两件合格窗「前窗末 → 后窗起」 | 1326 − 837 = **489 ms** |
| L60 同上 | 1031 − 604 = **427 ms** |
| 已定格的冻结时长 `DESYNC_FREEZE_MS` | 200 ms（D-128b） |
| **取 220 ms** | 比双击宽 70ms+，比最早真实第二按（427ms）留 **207ms** 余量 |

即：**第一次点击与第二次点击之间，最短间隔 220ms**；点击再早一律忽略并提示。

**边界**：
- 保护只作用于"同一关同一轮尝试里的第二次定格"；重开本关/下一次尝试会清零。
- 保护不影响判定口径（仍是轮廓重合面积），也不改变窗口毫秒。
- 断言：`modes_check` **S44**（连点 60ms 必须被忽略；间隔 600ms 必须正常定格）。

## 8. 「定格」的语义（D-134，2026-10-22 修正）

**定格 = 物体停在原地不动**，不是"画面暂停一下给个分数"。

| 次数 | 玩家看到 | 系统做什么 |
| --- | --- | --- |
| 第 1 次点击 | 被点到的那件**停住不再动**（略微压暗），另一件继续飞；**没有任何评级文字** | 记下该 mover 的 pct 与姿态（`frozenPose`），时间轴继续走 |
| 第 2 次点击 | 两件都停住 → 才弹出结算面板（评级 / 神级 / 星星） | `duoVerdict` 取两次里较差的一次 |

约束不变：
- 两次之间最短间隔 **220ms**（D-131 连击保护），更早的点击不判定、不扣机会；
- 判定口径仍是轮廓重合面积；窗口毫秒不变；
- 断言：`S17`（只定 1 个不算过）、`S19`（第一次只定格不出评级、未定格物体仍在动、attemptStart 不变）、`S44`（连击保护）。
