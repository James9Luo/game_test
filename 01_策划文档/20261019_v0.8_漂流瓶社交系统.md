## 0. 结论先行

**DIY 工坊取消；漂流瓶从"消息系统"重新定义为"成绩挑战系统"。**

这不是降级，是**换一个能做成的形态**。三条最关键的拍板：

| # | 拍板 | 推翻的原方案 |
| --- | --- | --- |
| ① | **神级是加速器，不是准入门槛** | "按神级次数决定收发资格与次数" → 新手神级率仅 6.0%，永远触发不到，网络形不成 |
| ② | **瓶子装"我的定格成绩卡"，不装自由文本** | 匿名 + 自由文本 → 95% 是垃圾内容，社交腐烂 |
| ③ | **助眠模式完全禁用社交** | 与"放松"调性冲突，且睡前接触陌生人内容是提审与体验双风险 |

## 1. 为什么砍掉 DIY 工坊

DIY 的原定位是"唯一的传播引擎"（GDD §4 标 P2 传播）。三个否决理由：

| # | 理由 | 展开 |
| --- | --- | --- |
| ① | **它和漂流瓶抢同一个位置，但成本高一个量级** | DIY 产出"关卡"，漂流瓶产出"成绩对比"。后者无需 UGC 审核、无需匹配服务、覆盖全部玩家而非只有创作者 |
| ② | **它开了一个绕过 k 门禁的注入口** | 内置道具全部过 `shapes_check` 的 k 门禁（D-022/D-043）；玩家上传一张近圆形图片 → 重合率怎么转都高 → 正是 R2「形状太对称 → 容错失效」 |
| ③ | **顶点上限与性能红线冲突** | 内置约束 12–48 顶点、D-014 红线按 48×2 定 0.5ms；DIY 上限 ≤64 顶点，叠加错拍关（双物体）即 64×2，超基准 33% |

**连带处置**：D-081 的 9 个备用道具（`banana duck cat octopus burger windmill satellite anchor dragon`）用途去掉 DIY 工坊一项，改为**无尽模式专用**（无尽模式立项时再定选池规则），不为消耗它们改周期或阶梯。

**接口保留**：GDD §4 模式表与 §10 商业化表中的"DIY 工坊"条目**划删除线保留一行**，注明"2026-10-19 取消，见 D-089"，不静默删除——后来人会搜到这个词。

## 2. 定位转变：从"陌生人对话"到"成绩挑战"

| | 原案（漂流瓶） | 新案（成绩挑战漂流瓶） |
| --- | --- | --- |
| 瓶子内容 | 文字消息 | **自动生成的定格成绩卡** + 可选预置短语 |
| 回收方式 | 随机陌生人捞 | 任何人可**挑战该成绩** |
| 回报确定性 | 随机，可能没有 | **确定**：对方一定玩完并回传结果 |
| UGC 审核 | 需要（文本） | **不需要** |
| 实现的匹配服务 | 需要 | **不需要** |

**核心逻辑**：异步 1:1 配对要求"双边同时在线且同时愿意"，在 DAU 量级下瓶子沉底率高，且玩家无法区分"没人捞"和"功能坏了"。改成"挑战"后，回报由对方的**意愿**决定而非**在线**决定——他是玩完之后才回传，可以是三天后。

---

## 3. 瓶子装什么（本版最核心的一条）

**玩家的游戏过程天然产出一种别处没有的内容：一次定格的精确数据。**

```
第 42 次神级 · 重合率 96.2% · 少转了 3° · 差 8ms · 道具：章鱼 · 第 9 关
```

这串数字**不需要用户创作**，且：

- 比"我打了 95 分"具体得多，有炫耀价值
- 天然可比较——"你能超过 96.2% 吗？"
- 不会像文本一样过期，数字永远有效

### 3.1 卡片内容（全部来自判定返回值，不在 UI 层拼字符串）

| 字段 | 来源 | 展示 |
| --- | --- | --- |
| `pct` | `judge()` 返回 | 主数字，大字 |
| `rating` | `ratingOf(pct)` | 徽章（神级为金环） |
| `deltaMs` / `angleDeg` | 判定三输出 | "少转 3° · 差 8ms" |
| `godCount` | 本地累计 | "第 42 次神级" |
| `propId` | `level.shapeId` | **身份**（见 §5） |
| `levelId` / `sceneId` | 关卡 + 当前场景 | 复现用（D-080 的 `?scene=` 扩展） |

### 3.2 可选短语：只给枚举，不给输入框

约 30 条预置短语 + 表情/道具图标，**客户端不存在任何自由文本控件**。

例：「这关我卡了 3 次」「这个形状有点难认」「差一点点就神级了」。

**理由**：自由文本会同时引爆内容审核、恶意引流、骚扰举报三类问题，而收益远低于成本（见 §2 收益列）。首版不做，等有真实留存数据再评估。

## 4. 资格与额度（推翻"神级准入"）

| 档 | 条件 | 每日瓶子额度 |
| --- | --- | --- |
| 未通关 | — | **0** |
| 首次通关 L1 | 通关即可 | **1** |
| 神级累计 ≥10 | 每 10 次神级 | **+1**（上限 3） |

**三条硬约束**：

1. **神级是加速器不是门槛**——D-015 实测新手神级率 6.0%，用它当准入会让前几天的用户永远接触不到社交，网络无法形成。
2. **绝不污染核心**：瓶子额度**不得**参与 `judge` / `stars` / `bestScore` / 星级 / 连击任何一项。一旦玩家发现"少定格几次就少几个瓶子"，它立刻变成压力源，与 relax 调性直接冲突。
3. **不设"分享才能领瓶子"**：直接撞微信诱导分享红线（2025 年平台已明确加强）。所有入口纯自愿。

### 4.1 助眠模式：额度 0，且不出现在广场

理由三条，任一条都够：①睡前刷陌生人内容是焦虑源；②D-049 已定助眠不记分不参与排名，社交排名同理；③提审风险。

## 5. 身份：道具即身份

**不要匿名 ID，用你手里的道具。**

> "一个抱着章鱼的玩家"  ≫  "用户 12345"

- 有归属感，不涉及任何个人信息
- 15 个内置道具都有性格（章鱼、火箭、马桶、风车），玩家会为了**展示与收集**而参与
- 这比空 ID 有粘性得多，且是现成的美术资产，不需要额外 UI 设计

**约定**：一个玩家对外展示的道具 = 当前进度中最靠前的那一件（或玩家自选，v0.8 不做自选）。

## 6. 频率与节奏

| 项 | 值 | 理由 |
| --- | --- | --- |
| 每日额度 | 1–3 个（见 §4） | 社交一旦变成"今天还没收瓶子"的日常任务，会和放松调性冲突 |
| 空罐冷却 | 48h 无互动则不再提示 | 防"玻璃罐焦虑"——反复回来看有没有人捞 |
| 不推送 | **不做任何主动推送** | 只在玩家自己进入时展示 |

---

## 7. 对比方式：比中位，不比排名

**不做全站排行榜、不做"你超过了 xx% 的人"。**

只展示：①我最好的一次；②广场里与我同一关卡的**中位水平**。

理由：全站排名在一个 relax 调性的游戏里是调性错误，且会持续制造挫败。中位对比给出的是"我比一半人好"——这是正反馈，而且不依赖他人规模。

## 8. 安全与合规红线

| # | 红线 | 说明 |
| --- | --- | --- |
| ① | **无自由文本** | 客户端零输入框（§3.2） |
| ② | **无陌生人私聊出口** | 一旦有私聊，UGC 的全部风险都会回来 |
| ③ | **不采设备标识 / 昵称 / 头像** | 与埋点表 §1「不做用户画像、不采设备唯一标识」一致；`owner` 用可轮换的伪名哈希 |
| ④ | **不做"分享得瓶子"** | 诱导分享红线 |
| ⑤ | **举报 + 拉黑**必须有 | 无文本的当下只针对"卡片本身让人不适"（如恶意刷神级数），仍需入口 |
| ⑥ | **瓶子卡必须带 `sceneId`** | 接收方看到的背景要和你一致，复用 D-080 的 `?scene=` |

## 9. 数据结构

**这是本项目第一个真正需要服务端的特性**（此前分享/广告/埋点都只留了接口，见 `04_项目管理/交付说明_v0.1.md` §5）。最小可用形态：

```jsonc
// 上行：提交一张瓶子卡（只发生在他人挑战成功回传时）
{
  "bottleId": "b_xxxxxxxx",
  "ownerHash": "rotating-pseudonym",   // 可轮换伪名，非设备标识
  "propId": "octopus",
  "levelId": 9,
  "sceneId": "night_station",
  "pct": 96.2, "rating": "god",
  "deltaMs": 8, "angleDeg": 3,
  "godCount": 42,
  "phraseId": "so_close",              // 枚举，可为空
  "createdAt": 1750000000000
}

// 下行：拉取广场
{ "items": [ /* 上行结构，不含 ownerHash */ ], "medianPct": 88.4, "serverTime": 1750000000000 }
```

**建议实现**：微信云开发（云函数 + 云数据库）或同类 serverless。理由：①免运维；②与小游戏生态同账号体系；③数据量级在"每天几千条"级别，不值得自建服务器。

## 11. 验收断言

> 沿用 `tools/modes_check.mjs` 的 S 编号，接在 S22a/S22d 之后。

| # | 项 | 判据 |
| --- | --- | --- |
| S23 | **解锁门槛** | 未通关 → 额度 0；通关 L1 → 额度 ≥1；额度随神级累计单调不减 |
| S24 | **不污染核心** | 同一 `pressMs` 下，改动瓶子额度**不改变** `pct/rating/score/pass/stars` 逐位相等（M17 的扩展口径） |
| S25 | **助眠隔离** | relax 模式下额度恒为 0、不出现在广场、不产生 `bottle_send` |
| S26 | **无自由文本** | 客户端不存在文本输入控件；上行 JSON 只可能出现枚举值 `phraseId` |
| S27 | **身份无 PII** | 上行字段集不含设备标识 / 昵称 / 头像；`ownerHash` 不可由 `propId` 反推 |
| S28 | **场景可复现** | 瓶子卡的 `sceneId` 渲染优先于本机 `localStorage` 场景设置（D-080 扩展） |
| S29 | **不诱导分享** | 全代码路径 grep 不到"分享/转发得瓶子"类分支；所有社交入口均可跳过且不损失任何进度 |

## 12. 风险

| # | 风险 | 概率 | 缓解 |
| --- | --- | --- | --- |
| R-瓶-1 | **池子太小 → 广场空** | **高** | 首日用内置标杆成绩（系统身份）填充，保证广场永远不空；`bottle_view` 的 `empty` 埋点专门盯这条 |
| R-瓶-2 | 社交做成任务、变成负担 | 中 | 上限 1–3/天；48h 无互动不提示；不做推送 |
| R-瓶-3 | 审核判为 UGC 或诱导分享 | 中 | 无自由文本 + 纯自愿入口 + 不做分享得瓶子（S26/S29 提前拦住） |
| R-瓶-4 | 服务端成为单点故障 | 中 | 拉取失败时降级为"看自己的最好成绩"本地页，**不得让社交故障挡住游戏本体** |
| R-瓶-5 | 与调性冲突（攀比焦虑） | 中 | 只比中位、只比自己最好（S7） |
| R-瓶-6 | 瓶子额度被玩家当作刷分目标 | 中 | S24 断言守住"不影响任何核心数值"；额度只增不减、无消耗 |
