# 埋点与验收标准 · 《定格瞬间》 v0.1

> 2026-10-18 · 主策划 · 规则：**每条设计点必须对应一个可验证的数据或行为**，否则不进版本。

## 1. 事件表（v0.1 只上这 7 个，宁少不滥）

| 事件 | 触发时机 | 参数 | 用途 |
| --- | --- | --- | --- |
| `app_open` | 启动 | `ver, platform, cold(bool)` | 基线 |
| `level_start` | 进入关卡 | `lvl, prev_lvl, retry_count` | 卡关定位 |
| `attempt` | 物体每次进场 | `lvl, attempt_idx, seed, cycle_ms, jitter, perfect_ms` | 复现与调参 |
| `judge` | 按下并出分 | `lvl, attempt_idx, pct, rating, delta_ms, angle_dev, offset_px, is_pass, score, combo, phase_ms` | **核心：判定分布** |
| `level_clear` | 通关 | `lvl, stars, attempts_used, best_pct, time_sec` | 星级/难度曲线 |
| `share_click` | 点分享/录屏 | `lvl, pct, rating, is_fail, channel`（**`channel` 值填场景 id**：`night_station` / `noon_window` / `minimal`） | 传播率 + **「分享可复现」验收**（规格 §5.2 B-a/b/c；步骤见 `04_项目管理/验收记录_v0.7.md` 表三） |
| `error` | 运行时异常 | `msg, stack_hash, lvl, phase` | 稳定性 |

**不做**：不做用户画像、不采设备唯一标识、不采通讯录。判定数据只到 `pct/delta_ms` 粒度。

> **`share_click.channel` 口径（v0.7 补登 · 2026-10-18 · 测试运营）**
>
> 1. **值 = 场景 id**（`night_station` / `noon_window` / `minimal`），不是渠道字符串（微信/朋友圈/复制链接由平台侧日志提供，本表不重复采）。
> 2. **它服务于「分享可复现」这条验收**：分享 = 一条链接、带 `?scene=<id>`，接收方冷启动打开即同款背景（v0.7 §5.1 / D-080）。
> 3. **对账规则**：`channel` 必须与链接里的 `scene` 参数**对得上**——对不上即说明文案里的场景名与实际链接不一致，**该项判验收失败**（B-a），不允许"埋点对了就行"。
> 4. 由此推出的验收动作：先在 A 侧点分享、拿到链接原文，再核该次 `share_click` 的 `channel` 与链接 `scene` 一致（台账见 `04_项目管理/验收记录_v0.7.md` 表三 S3/S5/S11）。
> 5. 现状登记：**未执行**（B1 分享链接尚未交付，2026-10-18 23:30）。

## 2. 设计点 → 验收标准（这是本文件的重点）

| # | 设计点 | 埋点/行为 | 验收阈值 | 不达标怎么办 |
| --- | --- | --- | --- | --- |
| V1 | 3 秒内看懂 | 5 人无提示试玩录像 | ≥4 人首次按下时物体已进场且方向正确 | 改首页演示动画，不改规则 |
| V2 | 不算太难 | `judge` 中 L1 `is_pass` 比例（新手档） | 60%–85% | 调 L1 `cycle_ms` |
| V3 | 不算太简单 | L1 `rating=god` 占比 | 3%–8% | 同上（反向） |
| V4 | 有"就差一点" | `judge` 中 `pct ∈ [40,60)` 占比（L5–L9） | 25%–35% | 调中段 `turns` |
| V5 | 高光稀有 | 全关 `rating=god` 占比（熟练档） | 2%–5% | 调 `star3_rate` 或窗口 |
| V6 | 能学会 | `attempt → attempt` 的 `pct` 均值提升（同意关） | 第 2 次 ≥ 第 1 次 +8 个百分点 | 结算文案加强"早/晚"提示 |
| V7 | 不劝退 | `level_start` 后未产生 `judge` 就退出（流失） | < 8% | 缩短进场等待，去掉多余动画 |
| V8 | 想分享 | `share_click / level_clear` | ≥ 8% | 结算页把分享按钮提前、加"失败也发" |
| V9 | 复现一致 | 同 `seed` 的 `judge` 结果 | pct 完全相同（±0.01） | 判定不是纯函数，P0 |
| V10 | 冻结跟手 | 按下 → `phase_ms` 冻结 | ≤ 16.7ms | P0 缺陷 |
| V11 | 判定够快 | `judge` 单次耗时 | ≤ 0.2ms（40 顶点） | 见核心说明的优化项 |
| V12 | 双轮廓不失衡 | L10/L15 两个物体 `pct` 差 | 均值差 < 15 个百分点 | 检查两条车道目标位置是否对称 |

## 3. 上线首日看板（4 个数字，多一个都不看）

| 指标 | 计算 | 红线 | 含义 |
| --- | --- | --- | --- |
| 首关通关率 | L1 `is_pass` / L1 `judge` | < 50% → 改 | 门槛是不是太高 |
| 第 5 关到达率 | `level_start.lvl>=5` / `app_open` | < 25% → 改 | 前 4 关有没有劝退 |
| 神级出现率 | `rating=god` / `judge` | < 1% 或 > 8% → 改 | 高光是否稀有可复现 |
| 分享率 | `share_click` / `level_clear` | < 5% → 改入口 | 有没有传播瞬间 |

## 4. 数据纪律

- 埋点参数**只允许来自配置与判定返回值**，不许在 UI 层临时拼字符串。
- 上报失败要落本地并在下次启动补传（最多 200 条）。
- 任何新增埋点必须在本表登记「用途」，没有用途的字段不采。
- **A/B 只在两个地方允许**：结算页分享按钮位置、失败后重试的等待时长。其余改数值一律走版本，不做灰度。
