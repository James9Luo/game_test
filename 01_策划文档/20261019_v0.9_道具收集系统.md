## 1. 为什么收集是正解

15 个道具定义了却进不了关卡（D-087 已证明：可辨识关集中在 40–64ms 窗口需求，任何换形都要把单关难度挪 20–60ms，"那已经不是换内容，是改难度"）。

**收集系统把"道具"和"关卡难度"彻底解耦**：

| | 换形进关（已作废） | 收集系统（本版） |
| --- | --- | --- |
| 动关卡表 | 动 → 破 S8 / 阶梯 | **不动** |
| 窗口阶梯 | 要重解 | **零影响** |
| 美术增量 | 每个道具都要重校 k、跑三级导出 | **零**（`pts`/名字/k 全现成） |
| 那 15 个道具的归宿 | 无 | **稀有收集池** |

## 2. 收集规则

### 2.1 池子口径（以数据为准，纠正 D-081 的 9 个）

核对 `shapes.json`(36) × `levels.json`(60 关) 的实际交集：

| 项 | 数量 | 说明 |
| --- | --- | --- |
| 道具总数 | **36** | 图鉴总数 |
| 挑战 60 关实际使用 | **21** | 主线池 |
| **挑战未使用（稀有池）** | **15** | `banana duck cat octopus burger tv skateboard headphone saxophone cactus dino windmill satellite anchor dragon` |
| 助眠 60 关实际使用 | 16 | 含 `tv` `skateboard`（这两个挑战没有） |

> **口径纠正**：D-081 写「备用池 = 9 个」，那是 D-087 换形作废**之前**的口径。实际从未进过挑战关卡的是 **15 个**，本版以 15 为准，**D-081 随之作废**（见 D-092）。

### 2.2 两条来源

| 来源 | 条件 | 解锁数 |
| --- | --- | --- |
| **主线** | 首次通关挑战模式第 N 关 | **21**（关卡表里实际那 21 个） |
| **稀有** | 累计神级达阈值（见 §2.3） | **15** |

### 2.3 神级阈值表（**推算值，必须校准**）

> ⚠️ **本表是推算，不是实测。** 本机无 node，`tools/sim.mjs` 跑不了（D-012 同因）。
> 推算依据：`数值与判定表 §6.1` 的神级率 × **每关平均 2 次尝试** × 60 关 ≈ 120 次判定。

| 技能档 | 神级率 | 推算全程神级次数 |
| --- | --- | --- |
| 新手 σ=130 | 6.0% | ≈ 7 |
| 普通 σ=90 | 8.6% | ≈ 10 |
| 熟练 σ=60 | 12.8% | ≈ 15 |
| 高手 σ=35 | 21.5% | ≈ 26 |
| 顶级 σ=20 | 36.6% | ≈ 44 |

**稀有池 15 个的解锁阈值（累计神级次数）**：

```
1, 2, 3, 4, 5, 6, 7, 9, 11, 14, 17, 21, 25, 31, 44
```

曲线意图：新手能拿 7 个（早期正反馈足），熟练约 10 个（有追求空间），**顶级 44 次刚好全满**（有终点）。

**校准方法**（拿到 node 必做）：跑 `node tools/sim.mjs --n=6000`，取表 A 的各档神级率，按 `全程神级次数 ≈ 60 关 × 每关平均尝试 × 神级率` 重算；若"每关平均尝试"实测值不是 2，本表整体平移。**阈值表本身写成配置**（`assets/resources/config/collection.json`），改表不改逻辑。

## 3. 图鉴

36 格，**按来源排序**（主线 21 → 稀有 15，D-098）；**不要按 tier 分组**——那份分组在 `美术_轮廓规格.md` §3.2，是换形前的历史值。

### 3.1 每格直接复用现成数据，不新画任何东西

> **2026-10-22 更新（D-113 / D-114 / D-125 / D-135）**：图鉴格已从「多边形剪影」改为**贴图**，未点亮格用**同源灰化**（同一张图 source-in 灰化、α0.55），不是另画一张剪影。理由：锁定格用多边形、点亮格用贴图，两张轮廓对不上，玩家会以为图鉴在骗人（真实踩过：章鱼锁定是旧多边形）。

| 展示 | 数据来源 | 是否现成 |
| --- | --- | --- |
| **格子主图（已点亮）** | `03_交付素材/gallery_sprites_112/<id>.png`（112px，格 104px 1:1）；详情 240px 用 256px 源 | ✅ 36/36 |
| **格子主图（未点亮）** | 同一张贴图 → `source-in` 灰化 + α0.55（`buildGreySprite`） | ✅ |
| 轮廓（回退态） | `shapes.json` 的 `pts`（贴图未加载/缺失时自动回退，不崩） | ✅ |
| 名字 | `shapes.json` 的 `name` | ✅ |
| **一句话辨识点** | `collection.json.items[*].hint`（换形后已按新结构改写） | ✅ |
| 难度档 | `k` 值 → **5 档**：敏感 / 偏敏感 / 舒适 / 偏宽容 / 极宽容 | ✅ |
| 尺寸 / 顶点 | `shapes.json`（顶点 12–80，D-119） | ✅ |

> **不要从这里抄 k 或档位**：逐件的 k / 档 / 池 / 进关在 `20261022_v1.2_道具总表.md`，本节只讲图鉴怎么取数。
> 旧的「辨识点抄 `美术_轮廓规格.md §1`」已失效——那份表是换形前的历史值。

### 3.2 未解锁状态：贴图灰化 + 慢速摆动（±15°）

> **2026-10-22 更新（D-114）**：不是"灰色剪影另画一张"，而是**同一张贴图 `source-in` 灰化、α0.55**——两张图轮廓必须严格同源（踩过：章鱼锁定是旧多边形、点亮是贴图，两张对不上）。

不用锁图标。剪影缓慢摆动既有过关未拆的期待感，又**直接呼应"歪一点就不给满分"的卖点**。

### 3.3 入口

结算页 + 首页给一个常驻入口。**完成度比排行榜更健康的目标**——分数会被超越，图鉴不会。

## 4. 助眠隔离（硬条款，不可协商）

| 项 | 助眠模式 |
| --- | --- |
| 图鉴 / 解锁 / 进度 | **全部没有** |
| 道具池 | **恒为全部 36 个**，不随任何进度变化 |
| 排名 / 分数记录 | 无（D-049 已有） |
| 倒计时 | 无（D-047 已有） |

**为什么助眠池是 36 个而不是现状的 16 个**：

1. 那 15 个"挑战没用"的道具（尤其 `windmill satellite anchor dragon` 等季 4 道具）**在收集系统里只能当图鉴条目**——解锁了也无功能出口。放进助眠池，它们同时成为**可玩内容**，零新增美术、零新增规则。
2. 助眠模式的定位是"听音乐、玩解压"，**内容丰富度是它唯一的竞争力**。16 个道具循环玩家一个月会腻，36 个不会。
3. "没有门"和"没有内容"是两件事。本版要的是**前者**，顺便把后者也做足。

> **与 D-047 的关系**：D-047 守的是"**结算与表现链**不得因模式而变"，本版不触碰该链。差异口径补记见 D-092。

### 4.1 助眠道具池编排（可选，锦上添花）

按 `scenes.json` 三场景各配一版顺序表（深夜 → 安静有质感的：咖啡杯/吉他/卫星/风车；午休 → 轻快圆润的：甜筒/冰淇淋/鸭子/猫）。

**成本极低（一张顺序表），且助眠玩家天天见——是能察觉的差异**，不像 D-063 里那些 ±10% 的隐形旋钮。**不要和收集系统绑在一起做。**

## 5. 三条硬约束

| # | 约束 | 理由 |
| --- | --- | --- |
| ① | **图鉴进度不得参与 `judge` / `stars` / `bestScore` / 星级 / 连击任何一项** | S24 教训：一旦"不收集就打不了高分"，收集立刻变压力源，与 relax 直接冲突 |
| ② | **不设任何每日收集任务** | 不签到、不"今日收集 1 个"、不给连续奖励、不提示"还差 X 个"。图鉴的驱动力必须是**好奇**（"那个剪影是什么？"），不是**焦虑**（"我今天还没收集"） |
| ③ | **助眠模式永远零进度** | 玩家躺下打开助眠，不知道自己在第几关、不知道收集了多少、不知道别人多少分——**什么都不用想** |

## 6. 埋点新增（登记用途，遵埋点表 §4）

| 事件 | 触发 | 用途 |
| --- | --- | --- |
| `collect_unlock` | 解锁一个道具 | 收集曲线：到第几关解锁多少、稀有池解锁节奏 |
| `gallery_view` | 打开图鉴 | 图鉴是否真的被使用 |
| `gallery_tile_tap` | 点某个格子 | **哪类道具最吸引人**（看美术下一轮该加动物还是器物） |
| `rare_unlock` | 解锁一个稀有道具 | 15 个稀有池的收集节奏；神级阈值是否需要调 |

`gallery_tile_tap` 值得单独说一句：它能直接回答"玩家最想收集的是动物还是器物",是后续美术投入方向的硬数据，目前没有任何其他埋点能给这个。

## 8. 风险

## 11. v0.9.1 收集体验重做（2026-10-20 · 用户反馈驱动）

> 用户原话：「收集到的道具没有反馈，完全没有乐趣」「图鉴系统很难进入，很难欣赏」。v0.9 只做到"能收集"，v0.9.1 补"想收集"。不做无尽模式（用户明确"先不做"）。

| 体验断点 | 改法 | 验收 |
| --- | --- | --- |
| 收集瞬间无反馈 | 结算面板上方「新图鉴」卡（剪影 56px + 名字 + `已收集 N/36`，主线 mint / 稀有金边，1.2s）；`newIds` 持久 NEW 点，看过详情即消；神级停留 1000→1800ms | S39 |
| 入口难找/点不中 | 首页 240×88 卡片（最近 3 件 + 计数）；挑战局内左下「📖 图鉴 N/36」胶囊 118×44（热区 162×88）；结算面板右上；通关页左上卡片；四处热区 ≥88；助眠四处全无 | S40 / S38 |
| 图鉴难欣赏 | **4×3 分页大格**（12 件/页 × 3 页，格 150×190、剪影 100px）；点格进 240px 全屏详情（解锁=完美姿态+呼吸，未解锁=灰剪影 ±15° 慢摆）；左右翻页、首末页灰显；有 NEW 打开自动落到 NEW 页 | S41 / S42 |
| 助眠出不出去 | D-100 落地：relax 局内「退出」可见胶囊 (24,136,88,44)，热区 88；挑战同点位不退出（仍判定） | S42 |

**体积**：480→500 KB（D-103），冻结 504622 B（98.6%）。
**未做**：真人 5 人盲测（脚本已写进验收记录，本轮无真人）、无尽模式、服务端。
